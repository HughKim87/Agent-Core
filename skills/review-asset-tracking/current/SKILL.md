# 대형 파일의 Git·자동 스냅샷 추적 검토

“이 프로젝트에서 Git이 읽을 큰 파일을 찾아줘”라는 요청이나, 새 모델 다운로드·도구 설치·렌더 출력·Git 초기화로 큰 파일이 추적에 노출되는 시점에 사용한다. 예정 경로도 파일을 쓰기 전에 검토할 수 있다. 기존 모델을 그대로 사용하거나 소형 문서만 편집하는 작업은 생략한다.

## 살펴볼 경로 고르기

1. 현재 프로젝트 또는 지정한 폴더를 기준으로 삼는다. Core가 연결돼 있으면 프로젝트 진입에서 선언한 `core_path`의 `rules/asset-reproducibility.md`와 해당 프로젝트 정책을 따른다. Core가 없는 프로젝트에서도 아래 절차로 제안할 수 있다.
2. 프로젝트가 선언한 보호 경로, 자격 증명, 중첩 저장소·Core, 외부를 가리키는 링크를 조사 범위에서 먼저 제외한다. 허용 범위를 좁힐 수 없으면 그 구간은 미확인으로 둔다. 프로젝트 전체의 파일 목록이나 로그 원문을 가져온 뒤 필터링하는 방식은 피한다.
3. 사용자가 경로를 열거할 필요는 없다. 허용된 설치 목록·잠금 파일·실행 정의·출력 설정에서 실제 모델 저장 위치와 도구·캐시·출력 경로를 찾는다. 필요한 디렉터리만 파일명·크기·개수 등 메타데이터로 살핀다. 한 파일이 크지 않아도 반복 생성되는 수천 개의 파일은 후보가 될 수 있다. 변경 빈도와 역할은 실행 정의나 기존 관측에서 확인한 만큼만 적는다. 자산의 본문을 읽거나 전체 해시를 계산할 필요는 없다.

## Git과 앱에서 각각 확인하기

- 기존 후보 파일은 스킬에 포함된 [Git 점검 도구](scripts/inspect_git_paths.py)로 한 번에 확인할 수 있다. `--root`에는 대상 작업 트리의 루트(초기화 전이면 해당 폴더), `--` 뒤에는 이미 범위를 확인한 개별 파일의 상대경로를 넘긴다. 아래는 호출 형태다.

  ```text
  python -B "<스킬 폴더>/scripts/inspect_git_paths.py" --root "<프로젝트>" -- "models/voice/weights.bin" "models/voice/manifest.json"
  ```

- 크기, 현재 인덱스 포함 여부, 표준 제외를 적용한 뒤의 미추적 수집 후보 여부, 일치한 ignore 규칙과 출처를 함께 본다. 이미 추적 중인 파일은 ignore에 일치해도 계속 추적된다. 부정 패턴이나 중첩된 규칙으로 다시 포함되는 파일도 있다. 디렉터리 전체를 제안할 때에는 그 안의 설정·원본·예외도 확인한다. 표본만 조사했다면 그 범위를 밝힌다.
- 도구를 실행할 수 없으면 허용된 파일에 한해 `git ls-files --cached`, `git ls-files --others --exclude-standard`, `git check-ignore -v --no-index`의 결과를 대조한다. 경로는 리터럴로 넘기고 명령 오류와 결과 없음을 구분한다. 신규 설치처럼 파일이 아직 없으면 목적지와 적용 예정 패턴을 따로 적는다. Git 초기화 전에는 기존 제외 설정과 예상 노출만 검토하고 초기화 후 확인할 항목을 남긴다.
- 앱의 자동 스냅샷은 사용 중인 앱의 대상 목록이나 해당 파일에 대한 기존 동작 기록에서 확인한다. 설정의 존재, 일반 Git의 제외 판정, 불완전한 로그에서 파일명이 보이지 않는 것만으로 앱의 실제 제외를 단정할 수 없다. 앱 근거가 없으면 `not_run`과 무엇을 관측하면 되는지 적는다.

## 경로별 제안 정하기

자산은 프로젝트 안에서 현재 위치에 보존하는 것을 기본으로 한다. 사용자가 프로젝트 밖 독립 보관을 명시적으로 요청한 경우에만 대상과 목적지를 다룬다. 일반 검토와 후속 개선 결과에서는 외부 보관 위치를 묻거나 미지정 값·미완료 항목·다음 작업으로 보고하지 않는다.

| 확인한 역할 | 제안과 근거 |
|---|---|
| 다시 받을 수 있는 모델·도구 설치본 | 실제 파일이나 전용 설치 하위 경로를 제안한다. 배포 출처, 고정 모델 리비전·변형 또는 도구 버전, 필요한 파일·설치 위치, 무결성 확인 방법을 기존 manifest·잠금 파일에서 연결한다. |
| 재생성 가능한 결과·캐시 | 입력과 생성 절차가 확인된 출력 경로를 제안한다. 작업 재현에 필요한 결과는 실행 정의·옵션·기준 출력을 연결한다. 버려도 되는 캐시는 경로와 제외 이유면 충분하다. |
| 수작업 원본·납품본·사용자가 학습한 가중치 | 프로젝트 안의 원본 경로와 현재 추적 방식을 유지한다. 원본 손실 후 동일 파일 복원을 요청받거나 추적 변경으로 기존 복원 수단이 사라질 때는 실제 복원 근거를 확인한다. 근거가 부족하면 현재 보존 방식을 유지하고 해당 한계를 설명한다. |
| 이미 추적된 자산 또는 역할이 섞인 폴더 | 추적 유지 항목과 좁혀서 제외할 후보를 명시한다. 인덱스 변경이 필요하면 로컬 원본·다른 사용자와 새 checkout에 미칠 영향 및 복원 위치를 설명한다. |

공유할 제외는 팀원이 checkout할 때 받는 `.gitignore`에, 장비 전용 예외는 해당 저장소의 로컬 exclude에 제안한다. 이미 제외된 파일도 규칙의 출처가 개인 전역 설정·로컬 exclude인지, 해당 `.gitignore` 자체가 버전 관리되는지 확인한다. 원하는 범위에서 이미 작동하는 규칙은 그대로 쓴다.

패턴은 설정 파일 위치를 기준으로 쓰고 경로에 Git 패턴 특수문자가 있으면 이스케이프한다. 소형 설정·설치 스크립트·잠금 파일·대표 출력처럼 보존할 이웃 파일도 대조한다. 예를 들어 `models/voice/`에 가중치와 설치 목록이 함께 있으면 `/models/voice/weights.bin`만 제안할 수 있다.

## 사용자에게 전달하기

가장 먼저 조치할 경로와 이유부터 답한다. 후보가 여러 개면 **경로·역할 / 관측한 Git·앱 상태 / 권장 패턴 또는 유지·보류 이유 / 해당 판단에 필요한 복원 근거**를 한 표로 묶는다. 요청한 판단에 필요한 값이 빠졌을 때만 확인한 출처와 보완할 위치를 짚는다. 후보가 없으면 확인한 범위만 짧게 보고한다.

Git 제외, 앱 자동 스냅샷 제외, 새 환경 복원·실행 결과를 각각 `pass`, `fail`, `not_run`, 근거 있는 `not_applicable`로 보고한다. 적용 전 제안과 이미 관측한 결과가 드러나게 쓴다. Git 제외 성공에는 인덱스와 미추적 수집 후보 양쪽에서 빠졌다는 근거가 필요하다. 결과 재현을 확인하려면 깨끗한 환경에서 대표 입력으로 실제 실행해 기준 출력과 대조해야 한다. 원본 바이트의 동일성, 허용 오차 내의 결과, 문서상 복원 가능성은 각자 관측한 수준으로 표시한다.

기본 산출물은 채팅의 제안이다. 이 검토만으로 설정·파일·인덱스·이력을 바꾸거나, 모델 설치·파일 이동·삭제·스냅샷 실행을 시작하지 않는다. 사용자가 별도로 적용 범위를 지정하면 그 범위의 후속 작업에서 실행과 검증을 다룬다.
