# Core 검토용 상세 채팅 인계 문서 항목

- 목적: 원래 대화 없이 검토할 수 있는 최소 근거와 개선 후보를 구성한다.
- 읽는 시점: 사용자가 상세 감사·독립 검토·전체 인계를 요청했거나, 후보의 복잡성과 위험 때문에 기본 보고만으로 재검토할 수 없을 때.
- 책임: 분석 에이전트가 근거를 작성하고 Maintainer가 현재성을 재검토한다.
- 상태: 선택형 상세 보고 규격. 기본 보고에 항상 적용하는 체크리스트가 아니며 활성 규칙이나 구현 설계도 아니다.
- 관련 권위: [채팅 분석 본문](../SKILL.md).

## 작성 원칙

- 판단에 영향을 주는 항목만 작성한다. 모든 항목을 채우기 위해 불필요한 배경을 늘리지 않는다.
- 자체 완결성은 전체 transcript 재현이 아니라, 원래 대화 없이 후보의 근거와 판단을 재검토할 수 있다는 뜻이다.
- 같은 원인의 반복 지적은 하나로 합치고 독립 사례 수로 세지 않는다.
- 프로젝트 세부사항은 일반화된 후보를 입증하는 최소 근거로만 남긴다.
- 파일 보고서라도 상세도가 자동으로 높아지지 않는다. 상세 보고가 필요한 이유가 있어야 이 규격을 사용한다.

## 문서 공통 정보

- 목적·작성 시점·책임·상태(`검토 후보 / 미승인`)와 Core 대조 여부는 항상 밝힌다.
- 분석 범위, 프로젝트 root, 실행 환경, 접근하지 못한 기록은 후보 판단이나 재현에 필요할 때만 포함한다.
- 프로젝트 파일 근거는 확인한 프로젝트 상대경로와 상태로 식별하며 관련 없는 파일은 수집하지 않는다.
- Core 기준이 없으면 `core_not_checked`로 표시한다.

## 후보별 정보

- ID와 요약, 필요한 개선 / 선택적 개선 / 근거 부족.
- 상황·기대 결과·실제 결과·사용자 교정·해결 및 검증 여부. 핵심 근거는 최소 발췌와 맥락으로 포함.
- 사실 / 추론 / 미검증의 구분, 원인 분류 또는 미분류 이유.
- 행동 개선 필요성과 Core 변경 필요성을 별도로 판정한다. Core를 대조하지 못했으면 후자를 확정하지 않는다.
- 도메인 고유명사를 바꿔도 유효한 일반화 문장과 특정 프로젝트에 남길 부분을 구분한다.
- 기존에 해결된 부분과 Core에 적합한 이유.
- 현재 소유자·예상 경로(미확정 허용), 적용 조건과 적용하면 안 되는 정상 사례.
- 일반화 근거와 부족한 근거, 최소 변경 제안, 미개선 영향.
- 검증 가능한 성공 조건·방법 및 `not_run` 항목.
- 승인·보류·거절 상태. 사용자가 승인하지 않은 것은 미승인 후보.

## 재개 요청

“이 후보의 근거를 확인하고 최신 Core와 비교해 중복, 소유권, 일반화 적합성, 최소 변경안과 검증을 보고한다. Core 변경은 정확한 대상·이유·현재 사용자 승인 후 수행한다.”

후보별 미확인 질문을 덧붙인다. 비밀이나 불필요한 원문 전체 대신 필요한 관측 근거만 남긴다.
