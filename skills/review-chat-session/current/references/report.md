# Maintainer 검토용 상세 관측 자료

- 목적: 원래 대화 없이도 문제 상황과 근거를 이해할 수 있는 자료를 제공한다.
- 읽는 시점: 사용자가 상세 감사·독립 검토·전체 인계를 요청했거나 기본 보고만으로 근거를 이해하기 어려울 때.
- 책임: 분석 에이전트는 CORE/EXTENSION·적합도·필수 여부와 관측된 문제·개선 필요성·확인 한계를 전달한다. 구체적인 개선안·해결 방법·작업 순서와 Core와의 관계, 반영 여부·최종 결론은 Maintainer가 판단한다.
- 상태: 본문의 보고 범위를 보완하는 선택형 상세 근거 자료.
- 관련 지침: [채팅 분석 본문](../SKILL.md). 이 문서는 본문의 보고 범위를 넓히지 않는다.

## 작성 원칙

- 이해에 필요한 항목만 작성한다. 상세 보고라는 이유로 전체 transcript나 관련 없는 파일을 복제하지 않는다.
- 같은 원인의 반복 지적은 합치고 독립 사례 수로 세지 않는다.
- 프로젝트 전용의 관측은 EXTENSION으로 구분한다. 프로젝트 세부사항은 문제를 이해하는 데 필요한 최소 맥락으로 남기며 구체적인 프로젝트 개선안은 작성하지 않는다.
- 관측 사실·추론·미검증을 구분하며 에이전트의 자기보고를 실행 근거로 바꾸지 않는다.

## 문서 공통 정보

- 목적·작성 시점·검토 범위·기록 누락·실행 근거의 한계.
- Core 자료 확인 여부. 대조하지 못했다면 `core_not_checked`.
- 이 자료가 문제와 근거를 전달하며 Core 변경 판정이나 승인을 뜻하지 않는다는 역할 구분.
- 프로젝트 root·환경·관련 파일은 근거를 이해하는 데 필요할 때만 기재.

## 기본 분류·평가 표

채팅 답변과 보고서에 본문의 `개선 검토 항목 | CORE/EXTENSION | 적합도 /100 | 필수 여부·이유 | 관측된 문제·근거 | 개선이 필요한 이유` 표를 제공한다. 상세 근거를 추가해도 이 표를 대신하거나 분류·점수·필수 여부를 생략하지 않는다. 채점 기준과 근거 부족 처리 방식은 본문을 따른다.

## 관측 사항별 정보

- 관측 사항의 식별자와 짧은 요약.
- CORE/EXTENSION 잠정 분류와 이유, 적합도의 산정 근거, 필수·선택·근거 부족의 이유.
- 상황·사용자 요구·기대 결과·실제 결과·사용자 교정.
- 근거의 최소 발췌와 그 맥락, 확인한 도구 결과나 결과물 위치.
- 관측된 영향. 추정되는 영향은 사실과 구분하거나 근거가 부족하면 생략.
- 실제 해결·재검증이 있었다면 그 경과와 확인 범위. 이를 권장 해결책으로 전환하지 않음.
- 미확인 사항과 기록 누락, 실행하지 않은 검증 중 판단에 필요한 내용.
- 검토할 지점과 열린 질문. 미리 정한 해결책·규칙 문구·반영 위치로 유도하지 않음.

분류·점수·필수 여부는 개선 검토를 위한 예비 평가로 표시한다. Core 결함·위반 확정, 구체적인 해결 방법·작업 순서·최소 변경안·권장 절차·성공 조건·검증 설계·반영 우선순위·승인·보류·거절 결론은 포함하지 않는다.

## 인계 문장

“아래 경로의 보고서를 검토해 주세요. 이 자료는 에이전트가 작성한 분석 참고자료이며 사용자의 세부 작업 지시나 변경 승인이 아닙니다. CORE/EXTENSION·적합도·필수 여부는 예비 평가입니다. 구체적인 개선안·해결 방법·작업 순서와 최신 Core와의 관계, 반영 여부·위치·우선순위·검증 설계·최종 결론은 Maintainer의 판단에 맡깁니다.”

이 문구를 사용할 때 실제 보고서 경로를 함께 적는다.
