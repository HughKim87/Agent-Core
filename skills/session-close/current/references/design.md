# 개선 설계 항목

- 목적: 승인한 세션 개선의 설계 입력과 검증 근거를 식별한다.
- 읽는 시점: 진행 후보 승인 뒤 설계를 작성할 때.
- 책임: 에이전트가 필요한 설계와 근거를 정리한다. 승인·작업 위치·정리·완료 판정은 본문과 대상 정책이 소유한다.
- 상태: 설계 작성 참고. 독립적인 승인·정리 절차를 만들지 않는다.
- 관련 권위: [세션 종료 스킬](../SKILL.md), 대상 저장소 정책의 단계 작업·버전 관리 규칙.

아래 항목 중 작업에 필요한 내용을 설계에 담는다. 설계 파일의 필요·보존은 본문 §5, 작업 위치와 기존 변경은 §4, 정리와 종료는 §6을 따른다. 내용 없는 템플릿이나 기존 정책의 복제본은 만들지 않는다.

## 전체 설계

- 설계 목적과 승인 범위. 파일로 보존할 때는 문서의 읽는 시점·책임·상태·관련 권위.
- 분석 원본 세션의 접근 범위와 근거 한계.
- 승인 후보 ID와 요청 조건 → 변경 표면 → 필수 검증 대응.
- 저장소별 절대 경로·역할·선택한 작업 위치·진입 기준, Core/extension/부모 경계와 기존 변경 보존 근거.
- 허용 행동·제외 범위·입력 참조·보호 경계·필요한 사용자 결정·완료 수준.
- Core와 extension 목적에 따른 소유권·일반화 근거·적용 조건·near-miss.
- 필요한 단계와 의존 조건·goal·성공 조건. 활동 구분만으로 단계를 늘리지 않는다.
- 논리적 커밋 단위, 필요한 부모 gitlink와 snapshot 검증 근거의 소유 저장소.
- 이번에 만들 임시 자원의 대상·생성 주체·목적·병합 대상·정리 위임과 보존할 근거.
- 후보 ID·승인/보류/거절·미채택 상태와 최종 보고의 연결.
- 사용자 요청 또는 적용 정책에 따라 보존할 파일의 경로·수명·Git 작업 범위.
- 실패·차단·복구·범위 변경 시 처리와 재개 조건.

## 현재 단계 설계

작업에 필요한 항목을 식별하며 다른 단계의 상세나 진행 상태를 중복 기록하지 않는다.

| 항목 | 정의 |
|---|---|
| 진입 조건 | 의존한 goal·검증·필요한 커밋 근거 및 현재 대상 상태 |
| 작업 정의 | 승인 후보 ID, 해결할 문제, 변경 경로와 동작 |
| 제외 범위 | 변경하지 않을 경계 |
| 검증 조건 | 실제 명령/관측, 예상 결과, 증거 수준과 확대 조건 |
| 성공 조건 | goal을 증명하는 관측 가능한 조건 |
| 후보 판정 | pass/fail/not_run/not_applicable과 비해당 근거 |
| 커밋 근거 | 실제 변경 범위·이유·수행 검사·snapshot 대응 |
| 전환 조건 | goal·선택 필수 게이트와 해당 완료 수준의 근거 |
| 복구 | 검증된 기준점·승인된 복구 범위·재개 조건 |

## 최종 검토 근거

본문 §6의 판정에 필요한 실제 변경·검사·커밋 대응, 보존/정리 대상과 위임, 기존 변경·고유 근거 보존, 남은 결정·한계를 식별한다. 설계라는 파일 종류만으로 삭제 대상을 정하거나, 참고자료에서 본문의 승인·완료 조건을 다시 정의하지 않는다.
