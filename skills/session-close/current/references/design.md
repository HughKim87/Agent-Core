# 개선 설계 항목

- 목적: 승인한 세션 개선을 검증 가능한 단계와 커밋으로 실행한다.
- 읽는 시점: 진행 후보 승인 뒤 설계를 작성할 때.
- 책임: 에이전트가 설계를 작성하고 사용자가 단계·성공 조건·승인 범위를 결정한다.
- 상태: 설계 작성 참고. 대상 저장소의 단계 작업 규칙이 정본이다.
- 관련 권위: [세션 종료 스킬](../SKILL.md), 대상 저장소 정책의 최신 단계 작업·버전 관리 규칙.

아래 항목 중 작업에 필요한 내용을 채팅 설계에 담는다. 설계 파일은 사용자의 명시적 파일 보존 요청이나 대상 정책의 요구가 있을 때만 작성한다. 내용 없는 템플릿을 저장하거나 기존 정책을 복제하지 않는다.

## 전체 설계

- 설계 목적과 승인 범위. 파일로 보존할 때만 문서의 읽는 시점·책임·상태·관련 권위를 함께 적는다.
- 분석 원본 세션의 접근 범위와 근거 한계.
- 승인 후보 ID와 요청 조건 → 변경 표면 → 필수 검증 대응.
- 저장소별 절대 경로·역할·승인 브랜치·진입 기준, Core/extension/부모 경계. 로컬 변경이 있으면 현재 위치에서 계속 / 별도 개선 브랜치·워크트리 / 중단·보류 중 사용자의 명시적 선택과 승인, 그 승인 범위를 확인한다.
- 허용 행동·제외 범위·입력 참조·보호 경계·사용자 결정·완료 수준.
- Core와 extension 목적에 따른 소유권·일반화 근거·적용 조건·near-miss.
- 단계 구성·의존 순서·단계별 goal·성공 조건. 활동 구분만으로 단계를 늘리지 않는다.
- 각 단계 커밋, 필요한 부모 gitlink 기록, 추적 파일 정리 커밋의 소유 저장소. 설계 파일의 작성·커밋을 승인받은 경우에만 0단계를 둔다.
- 이번에 만들 임시 파일·개선/통합 워크트리·개선 브랜치의 정확한 대상·생성 주체·목적·병합 대상·종료 정리 승인과 보존할 근거. 기존/공유 자원은 제외한다.
- 채팅으로 보고한 후보 ID·결정 상태와 최종 채팅 보고의 연결.
- 사용자가 파일 보존을 명시적으로 요청한 경우에만 보존 경로와 승인된 Git 작업 범위를 정한다. 검토·종료 보고를 위한 파일 생성이나 커밋은 기본 단계가 아니다.
- 단계 실패·차단·복구·범위 변경 시 처리와 재개 조건.

## 현재 단계 설계

각 단계에서 다음을 정의한다. 다른 단계의 상세나 진행 상태를 중복 기록하지 않는다.

| 항목 | 정의 |
|---|---|
| 진입 조건 | 이전 단계의 goal·검증·커밋 증거 및 이번 대상 상태 |
| 작업 정의 | 승인 후보 ID, 해결할 문제, 정확한 변경 경로와 동작 |
| 제외 범위 | 이번 단계에서 변경하지 않을 경계 |
| 검증 조건 | 실제 명령/관측, 예상 결과, 증거 수준 및 확대 조건 |
| 성공 조건 | 단계 goal을 증명하는 관측 가능한 조건 |
| 후보 판정 | pass/fail/not_run/not_applicable 기준과 비해당 근거 |
| 커밋 조건 | 정확한 stage 범위, 메시지에 남길 변경 이유·실제 검사, snapshot 대조 |
| 전환 조건 | goal 달성·선택 필수 게이트 pass·단계 커밋 확인 후 다음 단계 |
| 복구 | 마지막 검증 commit, 승인된 복구 범위, 차단/재승인 조건 |

## 정리 및 최종 성공 조건

- 승인된 개선만 구현되고 선택 필수 게이트가 실제 통과했다.
- 단계별 실제 commit snapshot과 검증 증거가 일치한다.
- 설계와 이번 작업 전용 임시 자원이 최종 트리에서 제거되었고 삭제가 커밋되었다.
- 실제 생성한 설계·단계별 커밋 이력은 유지된다. 고아 링크·중복 정본이 없다.
- 승인된 기존 로컬 변경은 보존되고 이번 개선의 미커밋 변경·미해결 충돌이 없다. 격리 워크트리는 clean이다.
- 보류·거절 후보와 남는 위험이 보고되었고 미결 결정이 없다.
- 최종 채팅 보고가 실제 상태와 일치하며, 파일 보존을 요청받은 경우에만 해당 파일의 승인된 보존 위치를 확인한다. 이번 호출이 만든 워크트리와 병합된 개선 브랜치는 종료 전에 정리되며, 기존 기준 브랜치와 다른 작업 자원은 보존된다.
- 이 조건이 모두 충족된 후에만 종료 표시를 출력한다.
