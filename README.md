# Agent Core

- 목적: Agent Core가 존재하는 이유와 설계 의도, 저장소의 구성 개요를 설명한다.
- 읽는 시점: Core가 해결하는 문제와 전체 구조를 빠르게 파악할 때.
- 책임: Core Maintainer가 목적·구조의 정본과 일치하도록 유지한다.
- 상태: 활성 개요. 정본이 아닌 파생 표현.
- 관련 권위: [Core 헌장](docs/CHARTER.md), [Kernel 범위](docs/KERNEL_SCOPE.md), [계층 구조](docs/ARCHITECTURE.md), [정보 소유 구조](docs/INFORMATION_ARCHITECTURE.md).

## 목적

AI 에이전트는 세션이나 도구가 바뀌면 작업 규칙, 안전 경계, 현재 문맥과 완료 기준을 다시 추측하기 쉽다. Agent Core는 여러 프로젝트가 함께 사용할 수 있는 도메인 중립의 정책·규칙·계약·검증기를 제공해, 서로 다른 에이전트가 같은 작업 환경을 복원하고 일관된 기준으로 작업하도록 돕는다.

Agent Core의 목적은 모델 자체의 추론 능력을 바꾸는 것이 아니다. 대화 기억에 의존하던 작업 기준을 선언된 파일과 검증 가능한 결과로 옮겨, 세션·에이전트·프로젝트가 달라질 때 생기는 품질 편차를 줄이는 데 있다.

## 설계 의도

- **공통 기반과 프로젝트 정보의 분리**: Core는 재사용할 공통 정책·규칙·계약·검증 구현을 소유하고, Consumer는 프로젝트 진입·정책·현재 상태·도메인 정보와 실제 데이터를 소유한다.
- **대화보다 선언과 근거 우선**: 에이전트가 기억이나 추측이 아니라 저장소에 선언된 기준과 실행 결과에서 작업 문맥을 복원하게 한다.
- **하나의 사실에 하나의 정본**: 목적, 구조, 호환성, 현재 상태처럼 책임이 다른 정보를 각자의 소유자에 두고 중복 정본을 만들지 않는다.
- **필수 기반과 선택 기능의 분리**: 공통 검증 Kernel은 독립적으로 성립하며, 추가 데이터 기능은 필수 경로에 영향을 주지 않는 선택 계층으로 격리한다.
- **검증 가능한 최소 계약**: 특정 프로젝트나 에이전트 구현에 결합하지 않고, 여러 환경에서 관측하고 재현할 수 있는 최소 공개 경계를 유지한다.

Core와 Consumer의 역할은 다음처럼 나뉜다.

```text
Agent Core
공통 정책 · 규칙 · 계약 · 검증기 · 선택적 공통 기반
                         ↓
Consumer
프로젝트 진입 · 정책 · 현재 상태 · 도메인 규칙 · 실제 데이터
```

## 저장소 구조

| 위치 | 역할 |
|---|---|
| `PROJECT_RULES.md` | Core 공통 정책과 행동별 규칙 선택 경로 |
| `rules/` | 작업 상황별 공통 절차, 안전 경계와 검증 규칙 |
| `docs/` | Core의 목적, 범위, 구조, 정보 소유권과 호환성 정본 |
| `src/core_check/` | 선언과 경계를 해석하고 검사하는 필수 검증 Kernel |
| `experimental/shared_data/` | 필수 Kernel과 격리된 선택적 공통 데이터 계약과 Runtime |
| `tests/` | 필수 정책·계약·검증기의 회귀 및 결함 주입 검사 |

구조와 의존 방향의 세부 정본은 [계층 구조](docs/ARCHITECTURE.md), Core와 Consumer가 소유하는 정보의 정본은 [정보 소유 구조](docs/INFORMATION_ARCHITECTURE.md)가 제공한다.
