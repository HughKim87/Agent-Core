# 독립 Core 1차 완료 판정 — 재검증 중

- 목적: 독립 Agent Core Kernel이 다음 단계로 넘어갈 수 있는 상태인지 종합 판정하고 알려진 한계를 소유한다.
- 읽는 시점: Core의 완성도를 확인할 때, Host 연결 단계를 시작할지 판단할 때.
- 책임: 에이전트가 증거를 감사하고 사용자가 완료를 승인한다.
- 상태: 활성 정본. 2026-08-13 Windows clean clone 실패로 기존 완료 판정 무효화. 내부 재검증 중.
- 관련 권위: [Core 헌장](CHARTER.md), [검증 수준과 완료 판정](VERIFICATION.md).

---

## 1. 현재 판정

**독립 Core 1차 완료 판정 무효. 내부 재검증 중.** Host 연결 설계는 시작하지 않는다.

기존 완료 판정 이후 Windows clean clone에서 정상 CRLF를 후행 공백으로 오인하는 결함과 회귀 테스트 실패가 확인됐다. §7의 무효화 조건이 성립했으므로 아래 기존 완료 증거는 역사적 감사 자료이며 현재 `pass`를 의미하지 않는다.

## 2. 기존 완료 조건별 결과 — 현재 재검증 대상

| 조건 | 결과 | 증거 |
|---|---|---|
| clean clone에서 게이트 통과 | `fail` | Windows clean clone에서 CRLF 오탐과 회귀 테스트 실패 재현 |
| 에이전트 진입 | `pass` | 진입 파일 3종이 모두 같은 정책 정본에 도달 |
| 자체 운영 | `pass` | 규칙 변경·검증 코드 변경·실패 주입 시나리오 3종 |
| 다중 에이전트 재개 | `pass` | 대화 없는 콜드 세션 2회 |
| 통합 검증 | `fail` | 단일 진입점은 존재하나 현재 회귀 테스트가 실패 |
| 실험 Runtime 처분 확정 | `pass` | 두 Runtime 모두 `제외`. 근거와 재검토 조건 명시 |

## 3. 헌장의 보장 달성 여부

| 보장 | 상태 | 근거 |
|---|---|---|
| G1 같은 정책 정본 도달 | 달성 | 콜드 세션 2회 모두 동일 경로로 도달 |
| G2 대화 없는 상태 복원 | 달성 | 콜드 세션이 첫 행동을 추론 없이 특정 |
| G3 위험 행동의 사전 정지 | 부분 | 정책과 규칙으로 정의. 실행기 수준 강제는 Core 범위 밖 |
| G4 완료 주장과 검증 근거의 연결 | 달성 | 게이트 판정값과 미실행 구분, 확대 보고 금지 |
| G5 실패 지식 재사용 | 부분 | 정본 8건 보존. 실제 재사용 사례는 이 저장소 안에서만 확인 |
| G6 같은 입력의 재현성 | 달성 | 컨텍스트 지문과 게이트 결과의 반복 일치 |

G3의 "부분"은 설계상의 경계다. 프롬프트는 권한 경계가 아니며 실제 강제는 실행기와 샌드박스가 소유한다. Core는 그 경계를 정의하고 위반을 탐지할 뿐이다.

## 4. 최상위 성과의 실측

| 성과 | 실측 |
|---|---|
| P1 Agent 교체 가능성 | 콜드 세션이 목표·범위·위임·차단을 정확히 재진술 |
| P2 반복 지시 감소 | 27개 단계 동안 정보 재설명 개입 0회 |
| P3 품질 일관성 | 시작 문맥이 정책과 상태 2개로 고정. 규칙은 route로만 선택 |
| P4 재개 가능성 | 상태 문서가 단계 수와 무관하게 일정 크기 유지 |

## 5. 알려진 한계

이 목록이 비어 있지 않다는 것이 이 판정의 신뢰 조건이다.

| 한계 | 내용 |
|---|---|
| 환경 검증 범위 | Python 3.10 하나에서만 확인했다. 상위 버전과 다른 운영체제는 미검증 |
| 의미 기반 라우팅 재현 | 규칙 route의 의미 기반 재현을 전 route에 대해 소진하지 않았다 |
| 실패 지식 재사용 | 다른 프로젝트에서의 재사용은 검증되지 않았다 |
| 미구현 검사 | 계층 배정 검사와 정본 복제 검사 일부가 아직 자동화되지 않았다 |
| 실제 Host | 두 번째 프로젝트 연결은 0회다. Host 관련 주장은 모두 미검증이다 |
| 한시 자료 | `tmp/` 의 과거 기록이 아직 종료되지 않았다. 삭제는 사용자 승인 대상 |

## 7. 이 판정을 무효화하는 조건

- clean clone에서 게이트가 실패한다.
- 콜드 세션이 상태 문서만으로 재개하지 못한다.
- 필수 검사 중 하나가 결함을 탐지하지 못하는 것이 확인된다.

위 셋 중 하나가 발생하면 완료 판정을 철회하고 해당 단계로 돌아간다.

현재 첫 번째 조건이 성립했다. 완료 복원 조건과 작업 순서는 [Core 내부 검증 개선 설계](CORE_IMPROVEMENT_BLUEPRINT.md)가 소유한다.
