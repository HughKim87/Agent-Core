# 버전과 호환성

- 목적: 지원 런타임, 공개 계약 버전, 호환·비호환 변경의 기준을 단일 선언으로 소유한다.
- 읽는 시점: 런타임 요구를 확인할 때, 공개 계약을 바꿀 때, 복구 지점을 찾을 때.
- 책임: 에이전트가 선언과 구현의 일치를 유지하고 사용자가 비호환 변경을 승인한다.
- 상태: 활성 정본. Stage 26 성공 게이트 통과.
- 관련 권위: [상시 정책](../POLICY.md), [계층과 의존 방향](ARCHITECTURE.md).

이 문서가 지원 버전의 유일한 선언이다. 다른 문서나 코드가 같은 값을 다시 적지 않고 이곳을 조회한다.

---

## 1. 선언

<!-- core-compatibility:v1 -->
```json
{
  "core_version": "0.1.0",
  "contract_version": 1,
  "python_min": "3.10",
  "required_dependencies": [],
  "optional_dependencies": []
}
```
<!-- /core-compatibility -->

이 블록이 기계 판독 정본이다. 게이트의 preflight가 이 값을 읽어 런타임을 검사한다.

## 2. 각 버전의 의미

| 버전 | 무엇을 가리키는가 | 언제 올리는가 |
|---|---|---|
| `core_version` | 이 저장소 전체의 배포 단위 | 어떤 변경이든 배포할 때 |
| `contract_version` | 공개 인터페이스와 규칙 계약의 세대 | 비호환 변경이 있을 때만 |
| `python_min` | 지원하는 최소 실행 환경 | 하위 환경 지원을 끊을 때 |

`core_version`이 올라가도 `contract_version`이 같으면 소비자는 바꿀 것이 없다.

## 3. 호환과 비호환

| 구분 | 예시 |
|---|---|
| 호환 | 규칙 문구 보강, 검사 추가, 실패 지식 추가, 오류 메시지 개선 |
| 비호환 | 공개 명령 제거·개명, 종료 상태 의미 변경, 결과 구조의 필드 제거, 규칙 소유자 제거, 라우팅 trigger 축소 |

비호환 변경은 `contract_version` 상승이나 명시적 이전 절차 없이 수용하지 않는다.

## 4. 의존성

필수 의존성은 표준 라이브러리뿐이다. 이 성질은 회귀 테스트가 강제한다.

선택 의존성을 추가하려면 그것 없이도 필수 검증이 통과해야 한다. 선택 기능의 부재는 실패가 아니라 `not_applicable`이다.

## 5. 텍스트와 줄바꿈 계약

- 추적되는 텍스트의 저장소 표준은 UTF-8과 LF다. `.gitattributes`가 checkout 형식을 정규화한다.
- 무결성 검사는 정상 LF와 CRLF를 같은 줄 종료로 해석한다.
- 줄 종료 직전의 공백과 탭은 줄바꿈 종류와 관계없이 위반이다.
- Git 정규화 정책과 검사기의 입력 해석은 서로 다른 책임이다. 정책이 없는 외부 입력도 정상 CRLF라는 이유만으로 실패시키지 않는다.

## 6. 복구

- 완료 이력과 복구 지점은 Git이 소유한다.
- 각 단계 후보는 그 commit snapshot을 임시 clean clone한 전체 게이트가 통과한 뒤에만 완료 이력이 된다.
- 작업 트리만 통과했거나 미추적 파일에 의존한 후보는 복구 지점으로 주장하지 않는다.
- 저장소 안에 백업 사본을 만들지 않는다.

## 7. 현재 알려진 제약

| 제약 | 내용 |
|---|---|
| 실행 환경 검증 범위 | Python 3.10의 과거 통과 기록과 Python 3.12.13의 I1 현재 checkout·Windows clean clone 통과 기록이 있다 |
| 운영체제 | 경로 처리는 표준 라이브러리만 사용하지만 여러 운영체제에서 검증하지는 않았다 |

이 표는 실제로 확인한 범위만 적는다. 확인하지 않은 환경을 지원한다고 선언하지 않는다.
