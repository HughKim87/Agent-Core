# 실험 기능의 격리와 승격

- 목적: 미래 기능을 보존하면서도 검증되지 않은 복잡성이 Kernel의 필수 경로가 되지 않게 한다.
- 읽는 시점: 실험 기능을 추가·승격·종료할 때, 어떤 기능이 필수 경로에 있어야 하는지 판단할 때.
- 책임: 에이전트가 격리를 유지하고 사용자가 승격과 종료를 승인한다.
- 상태: 활성 정본. 후보 Runtime 제외 판정과 재검토 조건 반영.
- 관련 권위: [Core 헌장](CHARTER.md) §7의 판정 기준, [계층과 의존 방향](ARCHITECTURE.md) §3의 격리 메커니즘.

---

## 1. 격리 규칙

| 규칙 | 내용 |
|---|---|
| 위치 | 실험 기능은 `experimental/` 에 둔다. Kernel 코드와 같은 패키지에 두지 않는다 |
| 의존 | 실험 기능은 기반 원시 계층만 의존한다. 검증 도구는 실험 기능을 import하지 않는다 |
| 등록 | 실험 기능의 검사는 검사 등록 인터페이스에 `optional`로 등록한다 |
| 부재 | 실험 기능이 없으면 등록 건수가 0이고 게이트는 `not_applicable`로 보고한다. 실패가 아니다 |
| 라우팅 | 상시 정책의 시작 경로와 규칙 라우팅이 실험 기능에 의존하지 않는다 |

이 다섯 규칙 중 처음 세 개는 자동 검사가 강제한다. 계층 경계 검사가 검증 도구의 실험 기능 import를 탐지한다.

## 2. 승격 조건

실험 기능을 필수 Kernel로 올리려면 다음을 **모두** 만족해야 한다.

1. Kernel 밖에 실제 소비자가 있다. 자기 테스트는 소비자가 아니다.
2. 헌장의 성과 P1~P4 중 최소 하나를 관측 가능하게 개선한다.
3. 그 개선이 추가되는 문서·명령·저장 비용보다 크다.
4. 실패와 복구 경로가 확인되었다.
5. 같은 결과를 기존 소유자나 Git으로 얻을 수 없다.

### 상태 저장 Runtime의 추가 조건

원장·이벤트·snapshot처럼 동시 쓰기가 가능한 상태 저장 Runtime을 추가하거나 승격하려면, 쓰기 성공 판정에 사용하는 해시·개수·버전을 **쓰기와 같은 잠금 내부 snapshot**에서 계산해야 한다. 잠금 해제 뒤의 사후 재읽기는 경쟁 구간을 닫았다는 증거가 아니다. 해당 Runtime이 실제로 도입될 때 정상·실패·경쟁 경로의 회귀 검증을 함께 추가한다.

## 3. 종료 조건

다음 중 하나에 해당하면 실험을 종료하고 제거한다.

- 승격 조건 1이 정해진 기간 안에 충족되지 않는다.
- 유지 비용이 관측된 개선을 넘는다.
- 같은 결과를 더 단순한 방법으로 얻을 수 있음이 확인된다.

종료는 삭제를 의미하며 사용자 승인이 필요하다. 종료된 실험의 이력은 Git이 소유한다.

## 4. 현재 실험 기능

**없다.**

참고 구현의 작업 상태와 지식·결정·수명주기 Runtime은 효용 비교 후 제외됐으며 이 저장소로 옮기지 않았다. 판정 근거와 재검토 조건은 [Kernel 범위](KERNEL_SCOPE.md) §8·§9가 소유한다.

과거 완료 snapshot에서 실험 기능이 없는 상태로 통합 게이트가 통과한 결과가 §1의 격리 구조에 대한 역사적 증거다. 현재 작업의 최신 게이트는 각 소비 저장소의 선언된 상태와 Git 이력이 소유하며, 실험 기능을 나중에 추가해도 이 성질을 다시 검증해야 한다.

## 5. 후보 Runtime 판정과 재검토에 사용하는 비교 기준

두 판정은 같은 기준으로 수행한다. 기준을 판정 시점에 정하면 결과에 맞춰 기준이 움직인다.

| 항목 | 측정 방법 |
|---|---|
| 재개 정확도 | 콜드 세션이 첫 다음 행동을 추론 없이 특정하는가 |
| 상태 어긋남 | 기록된 상태와 실제 저장소 상태가 다른 횟수 |
| 사용자 개입 | 작업당 정보 재설명 개입 횟수 |
| 명령 비용 | 한 번의 상태 갱신에 필요한 명령 수 |
| 문서 비용 | 유지해야 하는 활성 문서의 증가 수 |
| 복구 | 중간 실패 후 마지막 정상 상태로 돌아갈 수 있는가 |

비교 대상은 항상 두 가지다.

- **기준선**: Markdown 정본과 Git 커밋만 사용하는 현재 방식
- **후보**: 구조화 Runtime을 사용하는 방식

후보가 기준선을 이기지 못하면 승격하지 않는다. 동률이면 더 단순한 기준선을 유지한다.

## 6. 판정값

| 값 | 의미 |
|---|---|
| `채택` | 필수 Kernel로 승격한다 |
| `실험 유지` | `experimental/` 에 두고 승격 조건과 기한을 명시한다 |
| `제외` | 이 저장소에 옮기지 않는다 |

과거 후보 Runtime 판정은 두 항목 모두 `제외`였다. 재검토 조건이 실제로 발생해도 이 기준으로 다시 비교하며, 판정 작업의 성공이 곧 채택을 뜻하지는 않는다.
