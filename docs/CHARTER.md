# Agent Core 헌장 — 목적과 최종 책임

- 목적: Agent Core가 해결하는 문제, 보장하는 결과, 보장하지 않는 결과와 이후 모든 구성요소의 포함 판정 기준을 소유한다.
- 읽는 시점: Core에 무언가를 넣거나 뺄지 판단할 때, 그리고 Core의 목적 자체를 확인할 때.
- 책임: 사용자가 변경을 승인하고 프로젝트 에이전트가 승인된 문구를 유지한다.
- 상태: 활성 정본. Stage 1 성공 게이트 통과.
- 관련 권위: 최신 사용자 지시 > 이 문서 > [구축 설계도면](../AGENT_CORE_BUILD_BLUEPRINT.md)의 단계 지도.

---

## 1. 해결 대상 문제

AI 에이전트의 출력은 확률적이라 같은 요청에도 결과 품질이 흔들린다. 그러나 그 분산의 상당 부분은 모델 능력이 아니라 환경에서 온다. 세션이 바뀌거나 에이전트가 바뀔 때마다 다음 네 가지가 매번 새로 재구성되기 때문이다.

1. 무엇이 규칙인가
2. 지금 어디까지 됐는가
3. 무엇을 완료로 볼 것인가
4. 무엇을 건드리면 안 되는가

Agent Core는 이 네 가지를 대화 기억이 아니라 파일에 고정해 매 세션 동일하게 복원되게 하는 기반이다. 모델을 개선하는 것이 아니라, 모델이 매번 다시 추측해야 하는 범위를 줄여 분산을 낮춘다.

## 2. 목적

Agent Core는 서로 다른 프로젝트와 서로 다른 AI 에이전트가 대화 기억에 의존하지 않고 동일한 규칙·현재 상태·안전 경계·완료 기준을 파일에서 복원해 사용하게 하는 도메인 중립 운영 기반이다. 목표는 에이전트 출력의 품질 자체를 높이는 것이 아니라 환경에서 오는 품질 분산을 줄이는 것이며, 사용자가 같은 정보를 반복 설명하지 않고도 다른 에이전트가 작업을 정확히 이어받고, 위험한 행동은 실행 전에 멈추며, 완료 주장이 실제 검증 근거에 연결되도록 보장한다.

## 3. 주요 사용자

| 사용자 | 역할 | 1차 범위 |
|---|---|---|
| AI 에이전트 | 규칙·상태·경계를 읽고 행동하는 1차 소비자 | 포함 |
| 사용자 | 목표·승인·금지의 소유자이며 반복 설명 부담의 수혜자 | 포함 |
| Host 도메인 프로젝트 | Core를 사용하는 실제 프로젝트 | Stage 28 이후 |

Host를 1차 사용자에서 제외한 근거는 블루프린트 확정 결정 2번이다. Stage 27까지 Core는 자기 자신이 유일한 Host다.

## 4. 보장

Core가 책임지는 결과다. 각 항목은 관측 가능해야 하며, 관측 방법이 없는 보장은 이 표에 넣지 않는다.

| ID | 보장 | 관측 방법 |
|---|---|---|
| G1 | 어떤 에이전트가 어디서 시작하든 같은 정책 정본에 도달한다 | 에이전트별 새 세션의 실제 읽기 경로 |
| G2 | 대화 기록 없이 현재 단계·차단·첫 다음 행동이 복원된다 | 다른 에이전트의 무대화 재개 |
| G3 | 승인 없는 삭제·이동·외부 쓰기·보호 데이터 접근·Core 변경이 실행 전에 멈춘다 | 위반 시나리오 주입 |
| G4 | 완료 주장이 실제 검증 근거에 연결되고 미실행이 통과로 기록되지 않는다 | 완료 보고와 검증 로그 대조 |
| G5 | 해결된 실패가 다음 작업에서 검색되어 반복을 줄인다 | 실패 지식의 검색·적용 여부 |
| G6 | 같은 입력에서 같은 규칙 선택과 같은 컨텍스트가 나온다 | 반복 실행 fingerprint 비교 |

## 5. 비보장

Core가 책임지지 않는 결과다. 이 표의 항목을 Core의 성과로 주장하지 않는다.

| ID | 비보장 | 근거 |
|---|---|---|
| N1 | 모델 자체의 추론 품질 | Core는 환경 분산만 다룬다 |
| N2 | 도메인 작업의 정확성 | 도메인 소유자의 책임이다 |
| N3 | 프롬프트만으로 권한을 강제하는 것 | 실제 경계는 실행기와 샌드박스가 소유한다 |
| N4 | 자동 실행·스케줄링·다단계 오케스트레이션 | 실사용 부적합으로 이미 폐기된 방향이다 |
| N5 | 사람의 승인을 대체하는 것 | Core는 승인 지점을 명시할 뿐 승인을 생성하지 않는다 |
| N6 | 구조화 데이터 저장소와 검색 엔진 | Stage 24·25의 효용 판정 전까지 필수 범위가 아니다 |

## 6. 최상위 성과

| ID | 성과 | 관측 지표 | 실패로 보는 상태 |
|---|---|---|---|
| P1 | Agent 교체 가능성 | 에이전트 B가 추가 설명 없이 올바른 첫 행동을 선택한다 | 목표·범위·승인 해석이 에이전트 간에 갈린다 |
| P2 | 반복 지시 감소 | 작업당 정보 재설명 개입 횟수 | 사용자가 이미 파일에 있는 사실을 다시 말해야 한다 |
| P3 | 품질 일관성 | 같은 요청에서 선택된 규칙·범위·검증 수준의 일치 | 세션마다 다른 규칙이 적용된다 |
| P4 | 재개 가능성 | 중단 지점에서 정확히 재개하고 완료분 재작업이 0이다 | 재개를 위해 대화 기록이 필요하다 |

### 6.1 정보 재설명과 권한 승인의 구분

P2가 측정하는 것은 정보 재설명 개입뿐이다. 두 가지는 서로 다르며 섞으면 안 된다.

| 구분 | 예시 | 처분 |
|---|---|---|
| 정보 재설명 | 이미 파일에 있는 규칙·상태·경계를 사용자가 다시 말하는 것 | 제거 대상. P2가 측정한다 |
| 권한 승인 | 삭제, 이동, push, 외부 쓰기, Core 변경에 대한 사용자 결정 | 유지 대상. 위임할 수 없으며 분산의 원인이 아니다 |

이 구분이 없으면 이후 단계에서 승인 게이트를 줄이는 방향으로 잘못 최적화된다.

## 7. 포함 판정 기준

Core에 무언가를 넣을지 판단할 때 아래 다섯 질문을 사용한다.

| ID | 질문 |
|---|---|
| C1 | 도메인 어휘와 특정 프로젝트 구조 없이 서술되는가 |
| C2 | P1~P4 중 최소 하나를 직접 개선하며 그 개선을 관측할 수 있는가 |
| C3 | 실제 작업에 소비자가 있는가, 아니면 미래 대비인가 |
| C4 | 기존 소유자·Git·문서로 같은 결과가 나오지 않는가 |
| C5 | 통과와 실패를 판정할 관측 가능한 검사가 있는가 |

### 7.1 판정 규칙

| 조건 | 판정 |
|---|---|
| 다섯 개 전부 통과 | 필수 Kernel |
| C3만 미충족 | 실험 기능. 격리하고 승격 기준을 부여한다 |
| C1 미충족 | 도메인. Core에서 제외한다 |
| C2 또는 C4 미충족 | 제외 |
| C5 미충족 | 검사를 만들 수 있으면 보류, 없으면 제외 |

### 7.2 판정 예시

이 표는 기준의 사용법을 보여주는 예시이며, 전수 분류는 Stage 2가 소유한다.

| 구성요소 | C1 | C2 | C3 | C4 | C5 | 판정 |
|---|:-:|:-:|:-:|:-:|:-:|---|
| 규칙 라우팅 | 통과 | P3 | 통과 | 통과 | 통과 | 필수 Kernel |
| 현재 상태·인수인계 | 통과 | P4·P1 | 통과 | 통과 | 통과 | 필수 Kernel |
| Core 변경 승인 게이트 | 통과 | P3 | 통과 | 통과 | 통과 | 필수 Kernel |
| 문서·링크·Schema 무결성 검사 | 통과 | P3 | 통과 | 통과 | 통과 | 필수 Kernel |
| 해결된 실패 지식 | 통과 | P3 | 통과 | 통과 | 통과 | 필수 Kernel |
| 구조화 work state Runtime | 통과 | 미확정 | 미충족 | 미확정 | 통과 | 실험. Stage 24가 판정 |
| 지식·결정·수명주기 Runtime | 통과 | 미확정 | 미충족 | 미확정 | 통과 | 실험. Stage 25가 판정 |
| 도메인 워크플로 | 미충족 | — | — | — | — | 도메인. 제외 |
| 정기 자동 보고 | 통과 | 미충족 | 미충족 | — | — | 제외 |

Runtime 두 항목의 C3 미충족 근거는 참고 구현에서 source·knowledge·decision·lifecycle state·work state·event의 실제 데이터가 모두 0건이고, 기록 저장소의 쓰기가 실제 저장소에서 의도적으로 차단되어 있다는 측정 결과다.

## 8. 이 문서의 한계

- G1~G6과 P1~P4의 관측 방법은 정의되었으나 아직 실행 가능한 검사로 구현되지 않았다. 구현은 Stage 14·15·22가 소유한다.
- C2와 C4의 판정에는 판단이 개입한다. 판단이 갈리는 항목은 Stage 2에서 근거와 함께 기록하고 미확정으로 남긴다.
- 이 문서는 Core가 무엇인지 정의하며, 어디에 무엇을 두는지는 Stage 3과 Stage 4가 소유한다.
