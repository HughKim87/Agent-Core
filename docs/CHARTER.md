# Agent Core 헌장

- 목적: Agent Core가 해결하는 문제, 보장·비보장과 포함 판정 기준을 소유한다.
- 읽는 시점: Core에 기능을 넣거나 뺄 때, Core 목적과 완료 기준을 판단할 때.
- 책임: 사용자가 목적·범위 변경을 승인하고 Core Maintainer가 정본을 유지한다.
- 상태: 활성 정본. 순수 Core와 consumer 계약 반영.
- 관련 권위: 최신 사용자 지시 > 이 문서 > [Kernel 범위](KERNEL_SCOPE.md)와 [계층 구조](ARCHITECTURE.md).

---

## 1. 해결하는 문제

AI 에이전트는 세션이나 도구가 바뀔 때 규칙, 현재 상태, 안전 경계, 완료 기준을 다시 추측한다. Agent Core는 공통 규칙과 검증 계약을 파일에 고정하고, 각 소비 저장소가 자기 상태와 도메인 정보를 같은 공개 계약으로 제공하게 해 환경에서 오는 품질 분산을 줄인다.

Core는 모델 자체를 개선하지 않는다. 서로 다른 에이전트가 같은 작업 환경을 복원할 수 있게 한다.

## 2. 목적

Agent Core는 도메인 중립 공통 정책·규칙·검증기를 제공하는 독립 저장소다. 승인된 선택 계층은 여러 소비 저장소가 재사용할 수 있는 공통 데이터 계약과 구현도 제공할 수 있다. Maintainer와 Host는 같은 Core commit을 전체 submodule로 사용하며, 프로젝트별 진입·정책·상태·보호 경로와 실제 Runtime 데이터는 부모 소비 저장소에 둔다.

Agent Core는 작업의 결과·실패·판단·경험 중 재사용 가치가 있는 지식을 선별해, 세션·에이전트·프로젝트가 달라져도 필요한 근거를 비용 범위 안에서 재사용함으로써 반복 작업의 품질 편차를 줄인다.

## 3. 사용자와 역할

| 사용자 | 책임 |
|---|---|
| AI 에이전트 | 선언된 정책·상태·경계를 읽고 route와 승인 절차를 따름 |
| 사용자 | 목표·금지·승인·최종 확인을 소유 |
| Maintainer 저장소 | 승인된 Core 변경과 검증, Core commit 게시를 담당 |
| Host 저장소 | 검증된 Core를 read-only로 사용하고 프로젝트 상태를 소유 |

## 4. 보장

| ID | 보장 | 관측 방법 |
|---|---|---|
| G1 | 구성된 소비 저장소의 지원 에이전트가 같은 Core 정책·소비 정책·상태에 도달 | Codex·Claude 새 세션의 실제 읽기 경로 |
| G2 | 대화 기록 없이 소비 저장소의 현재 단계·차단·첫 다음 행동을 복원 | 다른 에이전트의 무대화 재개 |
| G3 | 승인 없는 파괴·외부 쓰기·보호 데이터 접근·Core 변경을 실행 전에 중단 | 위반 시나리오와 실제 권한 거부 |
| G4 | 완료 주장이 실제 검증 근거에 연결되고 `not_run`이 통과로 기록되지 않음 | gate 결과와 완료 보고 대조 |
| G5 | 검증된 실패가 규칙이나 결함 주입 검사에 흡수됨 | 예방 소유자와 회귀 검사 |
| G6 | 같은 Core·consumer 입력과 route 선택에서 같은 context fingerprint를 생성 | 반복 실행 결과 비교 |

Core 자체 보장은 소비 상태 없이 `verify`와 `gate`를 실행할 수 있다는 것이다. G1·G2·소비 context는 계약을 충족한 소비 저장소가 있을 때만 성립한다.

## 5. 비보장

- 모델 자체의 추론 품질과 도메인 결과의 정확성
- 프롬프트만으로 강제되는 파일·네트워크·Git 권한
- 선언되지 않은 에이전트·운영체제·런타임의 자동 지원
- Host마다 다른 배포 파일이나 Core fork의 동기화
- 실제로 실행하지 않은 Host·권한 시나리오

## 6. 설계 원칙

1. 공통 Core와 프로젝트 상태의 소유권을 분리한다.
2. 하나의 사실은 하나의 정본만 갖는다.
3. 대화 기억보다 선언된 파일과 실행 결과를 우선한다.
4. 필요한 규칙만 route해 시작 문맥을 제한한다.
5. 프롬프트와 실제 권한 강제를 구분한다.
6. 검증되지 않은 기능보다 검증 가능한 최소 계약을 유지한다.

## 7. 포함 판정

새 구성요소는 다음을 모두 만족할 때만 필수 Core에 포함한다.

- 특정 프로젝트 이름·경로·도메인 어휘 없이 재사용된다.
- G1~G6 중 하나를 직접 제공하거나 검증한다.
- Host가 Core 안에서 수정할 필요가 없다.
- 표준 라이브러리만으로 필수 경로가 성립한다.
- 기존 더 단순한 계약으로 같은 결과를 얻을 수 없다.

소비 저장소의 현재 상태·도메인 규칙·보호 경로·자격 증명은 이 기준과 무관하게 Core에 포함하지 않는다.

필수 Core가 아닌 선택 계층에 구성요소를 보존·흡수할 때는 다음을 모두 만족해야 한다.

- 사용자가 기능 단위의 흡수 목적과 범위를 승인했다.
- 구현과 계약은 도메인 중립이며 실제 데이터는 소비 저장소가 소유한다.
- 기본값은 비활성이고 선택 계층 전체가 없어도 G1~G6과 필수 gate가 유지된다.
- 외부 소비자는 [호환성 선언](COMPATIBILITY.md)에 공개된 명령·schema만 사용하고 내부 Python 모듈을 직접 계약으로 삼지 않는다.
- 원본의 고유 계약·회귀 테스트·실패 예방 근거가 새 소유자에 연결되기 전에는 이전 원본을 제거하지 않는다.
