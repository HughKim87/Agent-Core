# 소비 저장소의 에이전트 진입 계약

- 목적: Core를 사용하는 저장소에서 Codex와 Claude가 같은 정책·상태에 도달하는 진입 파일 계약을 소유한다.
- 읽는 시점: 소비 저장소를 처음 구성하거나 지원 에이전트·진입 포인터를 바꿀 때.
- 책임: 소비 저장소 Maintainer가 루트 포인터를 제공하고 Core Maintainer가 공통 계약을 유지한다.
- 상태: 활성 정본. contract v2 소비 경계.
- 관련 권위: [Core 상시 정책](../PROJECT_RULES.md), [정보 소유 구조](INFORMATION_ARCHITECTURE.md).

---

## 1. 소유 경계

Core 저장소에는 `AGENTS.md`, `CLAUDE.md`를 두지 않는다. 두 파일은 Maintainer·Host 소비 저장소 루트가 소유한다.

| 에이전트 | 소비 저장소 진입 파일 | 책임 |
|---|---|---|
| Codex 계열 | `AGENTS.md` | 선언된 세 문서로 가는 Markdown 포인터만 제공 |
| Claude 계열 | `CLAUDE.md` | 같은 세 문서로 가는 `@` 포인터만 제공 |

## 2. 필수 대상과 순서

두 포인터는 정확히 다음 순서를 가리킨다.

1. 선언된 `core_path` 안의 Core 정책
2. 소비 저장소 정책
3. 소비 계약이 선언한 현재 상태

진입 파일에는 정책 본문, 현재 상태, 도메인 규칙, 권한 판단을 복제하지 않는다.

## 3. Core 내부 진입 파일을 두지 않는 이유

Codex와 Claude는 하위 디렉터리 지침을 발견·활성화하는 시점이 다르다. 특히 Claude는 부모 루트에서 시작해도 Core 하위 파일을 읽을 때 하위 `CLAUDE.md`를 활성화할 수 있다. 제외 설정은 Core 디렉터리에서 직접 시작할 때 절대 경계가 되지 않는다.

따라서 소비 저장소 루트만 자동 진입 파일을 소유한다. Core 내부 지침의 우선순위에 의존하지 않는 것이 두 에이전트에 공통으로 적용되는 해법이다.

## 4. 검증

- 두 포인터의 대상 목록과 순서가 정확히 같은지 검사한다.
- 포인터가 소비 계약의 `core_path`, 정책, 상태 경로와 일치하는지 검사한다.
- Core submodule에 자동 진입 파일이 없는지 Core 자체 검사로 확인한다.
- 실제 에이전트 동등성은 소비 저장소의 새 비영속 세션에서 별도로 검증한다.

합성 포인터 구조 통과는 실제 에이전트 검증을 대신하지 않는다.
