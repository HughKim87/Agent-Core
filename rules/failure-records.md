# 실패 기록

- 목적: 재사용 가능한 해결 실패만 보존하고 현재 미해결 차단과 구분한다.
- 읽는 시점: 실질적이고 일반화 가능한 실패를 기록하거나 재사용할 때, 같은 실패가 반복될 때.
- 책임: 에이전트가 기록과 검색을 수행하고 사용자가 새 정본 추가를 승인한다.
- 상태: 활성 규칙. L2 작업 계약 계층.
- 관련 권위: [상시 정책](../POLICY.md).

---

## 1. 실패 분류

| 분류 | 의미 | 처분 |
|---|---|---|
| 환경 | 런타임, 경로, 인코딩, 샌드박스 제약 | 원인이 환경이면 코드를 고치지 않는다 |
| 권한 | 승인 부재, 접근 차단 | 안전 정지다. 실패 지식이 아니다 |
| 입력 | 요청 모호, 대상 불명확 | 계약을 다시 세운다 |
| 계약 | 문서와 구현의 불일치 | 정본을 먼저 고친다 |
| 구현 | 코드 결함 | 재현 조건을 먼저 고정한다 |
| 검증 | 검사 자체의 결함이나 부재 | 검사를 먼저 고친다 |

**분류가 먼저다.** 서로 다른 분류의 실패를 같은 재시도로 묶으면 원인이 확정되지 않은 채 시도만 늘어난다.

## 2. 기록 대상

장기 실패 지식으로 보존하는 것은 다음을 **모두** 만족하는 실패뿐이다.

1. 원인이 확인되었다.
2. 해결이 확인되었다.
3. 해결이 검증되었다.
4. 같은 원인이 다시 발생할 수 있다.
5. 해결 방법이 자명하지 않다.

## 3. 기록하지 않는 것

| 대상 | 이유 |
|---|---|
| 미해결 차단 | 현재 상태 문서가 소유한다 |
| 거부된 승인 요청 | 예상된 안전 정지다 |
| 교정된 일회성 오타·인용 오류·옵션 실수 | 재사용 가치가 없다 |
| 일시적 도구 오류 | 재현되지 않으면 지식이 아니다 |
| 같은 원인의 두 번째 문서 | 기존 정본을 갱신한다 |

## 4. 기록 구조

각 실패 정본은 원인 하나를 소유하며 다음을 갖는다.

- 증상: 관측된 것
- 조건: 재현에 필요한 상태
- 확인된 원인: 추정이 아니라 확인된 것
- 실패한 접근: 시도했으나 해결하지 못한 방법과 그 이유
- 해결: 실제로 통한 방법
- 검증: 해결을 확인한 방법
- 예방: 같은 원인을 막는 규칙이나 검사

`확인된 원인`이 추정이면 그 사실을 명시한다. 추정을 확정으로 적으면 다음 세션이 잘못된 전제를 물려받는다.

## 5. 반복 실패의 처리

- 같은 목표가 세 번 연속 실패하면 같은 방법의 반복을 멈춘다.
- 멈춘 시점에 실패 유형, 확인한 원인, 시도한 방법, 대체 방법, 재시작 조건을 기록한다.
- 성공 가능성이 남아 있어도 멈춘다. 세 번째 실패까지 원인이 확정되지 않았다면 방법이 아니라 진단이 부족한 것이다.

## 6. 조건과 행동

- **조건**: 새 작업이 과거에 실패했던 영역에 진입한다.
  - **행동**: 기존 실패 지식을 검색하고 해당하는 예방 조치를 적용한다.
- **조건**: 실패의 원인이 아직 확인되지 않았다.
  - **행동**: 실패 지식으로 저장하지 않는다. 현재 상태의 차단으로 남긴다.
- **조건**: 기존 정본과 같은 원인의 실패가 재발한다.
  - **행동**: 새 문서를 만들지 않고 기존 정본에 조건과 검증을 보강한다.

## 7. 예외

- 사용자가 특정 실패의 기록을 요청하면 §2의 조건을 충족하지 않아도 기록한다. 단 미해결임을 명시한다.

## 8. 검증

- 미해결 실패가 해결된 지식으로 저장되지 않았는지 확인한다.
- 같은 원인의 중복 정본이 없는지 확인한다.
- 기록된 실패에 해결과 검증이 모두 있는지 확인한다.
- 새 작업에서 기존 실패 지식이 실제로 검색되고 적용되는지 확인한다.
