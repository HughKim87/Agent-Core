# 실패 처리와 예방책 흡수

- 목적: 예산·진전·확정된 외부 결과를 근거로 반복 실행을 통제하고, 해결·검증된 실패의 일반화 가능한 예방책만 기존 규칙·검사에 흡수해 재발을 줄인다.
- 읽는 시점: 결과 실패·무진전·불명확한 외부 결과·예산 소진에서 재시도나 중단을 판정할 때, 해결·검증된 실패의 예방책을 판단할 때.
- 책임: 에이전트가 명시된 예산·무진전 중단·예방 소유자를 관리하고, 사용자가 새 정본 추가를 승인한다.
- 상태: 활성 규칙. L2 작업 계약 계층.
- 관련 권위: [상시 정책](../PROJECT_RULES.md).

---

## 1. 실패 분류

| 분류 | 의미 | 처분 |
|---|---|---|
| 환경 | 런타임, 경로, 인코딩, 샌드박스 제약 | 원인이 환경이면 코드를 고치지 않는다 |
| 권한 | 승인 부재, 접근 차단 | 안전 정지다. 실패 지식이 아니다 |
| 입력 | 요청 모호, 대상 불명확 | 계약을 다시 세운다 |
| 계약 | 문서와 구현의 불일치 | 권위 있는 요구와 대조해 문서·구현 중 잘못된 쪽을 확인한다. 구현에 맞추려고 요구를 낮추지 않는다 |
| 구현 | 코드 결함 | 재현 조건을 먼저 고정한다 |
| 검증 | 검사 자체의 결함이나 부재 | 검사를 먼저 고친다 |

분류는 진단과 다음 방법 선택의 근거다. 분류 변경을 승인된 예산이나 중단 조건을 우회하는 수단으로 쓰지 않는다.

## 2. 예산과 무진전 중단

- 작업에 명시된 재시도·시간·비용·동시 실행 예산을 준수한다. 구체 한도와 계수 단위는 사용자 지시 또는 Consumer 운영 정책이 소유하며 방법·도구·하위 Agent 변경으로 예산을 우회하지 않는다.
- 같은 원인으로 실패했고 다음 시도에 원인 해소나 새로운 검증 근거가 없으면 반복을 중단한다. 숫자 한도 미도달이나 한도 미지정은 무진전 반복의 허가가 아니다. 필요한 경우 원인·대안·남은 위험을 보고해 다음 결정을 받는다.
- 외부 효과의 성공 여부가 불명확하면 첫 시도 뒤라도 상태를 확인하기 전 같은 효과를 반복하지 않는다. 상태 조회만 끝난 것이 아니라 실제 결과가 판명되어 재시도가 적절한지 확인해야 한다. 끝내 판명하지 못하면 중단하고 불확실성을 보고한다.
- 사용자 취소를 즉시 존중하고 취소된 결과를 향한 새 시도를 시작하지 않는다. 승인된 위해 제한·안전 복구와 최소 상태 확인·보고만 수행한다.
- 독립 실행은 공유 쓰기·권한·예산·결과 충돌이 없고 각 결과를 판정할 수 있을 때만 허용한다. 하나라도 불명확하면 직렬화하거나 해당 실행을 멈춘다. 진단 병렬화가 외부 쓰기 승인이나 결과 예산을 대신하지 않는다.
- 완료 조건을 통과한 뒤 발견한 별도 개선 제안은 실패 재시도로 세지 않는다. 현재 요청의 미충족과 별도 개선은 작업 계약 소유자가 구분한다.

예방하는 위해는 같은 원인의 무진전 변경과 불명확한 외부 효과의 중복 실행, 취소·예산 우회다. 이미 원인을 해소한 새 시도와 독립 진단은 막지 않되, 실행 전 권한·현재 결과·남은 예산을 확인한다. 고정 숫자나 모든 후보의 직렬화를 공통 안전 보장으로 삼지 않는다.

예산의 계수 단위와 수명은 사용자 지시 또는 Consumer 운영 정책이 정한다. Core는 사용자 메시지·세션 전환을 초기화 시점으로 정하지 않는다. 여러 세션에 걸친 작업 예산도 그 승인된 수명을 유지해야 한다.

임시 실패 상태는 Consumer가 실행 구간에 한정해 정의한 카운터·시도 순서·중단 상태다. 이 사건별 임시 상태는 현재 상태·핸드오프·실패 문서로 복제하지 않는다. 명시적으로 지속되는 작업 예산은 그 임시 상태와 구분해 Consumer의 단일 예산 owner에서 보존하고, 재개에 필요한 승인 범위·제약과 owner 참조를 현재 상태에 남길 수 있다. 수명이 끝난 임시 카운터를 다음 실행의 예산으로 승계하지 않는다.

## 3. 해결된 실패의 기본 처분

실패가 해결되고 검증되면 Agent의 일반화된 판단·행동 변경이 필요한지 먼저 구분한다. 구현에만 특정되고 그런 변경이 필요하지 않으면 기존 회귀 검사만 보강하며, 아래 규칙 흡수 절차는 적용하지 않는다.

1. 일반화된 판단·행동이 필요하면 가장 좁은 기존 규칙 소유자를 먼저 찾는다. 구별되는 trigger와 독립 책임으로 기존 소유자가 수용할 수 없을 때만 상위 라우터가 선택한 규칙 거버넌스에 따라 새 소유자를 판정한다.
2. 일반화 가능한 판단·행동은 활성 규칙 하나의 조건·행동에 한 번 표현한다. 테스트와 fixture는 관측 가능한 입력·결과·near-miss를 검증하며 독립된 정책 정본을 만들지 않는다.
3. 예방책이 실제 결함을 탐지하거나 기대 행동을 재현하는지 검증한다. 구조 검사·합성 모델·Agent 의미 재현을 구분하고 실제로 관측한 수준만 주장한다.
4. 별도 실패 이력 없이 다음 작업의 선택·검증·복구 판단이 같으면 처분을 종료한다.

검색·정규식은 검토 후보를 찾는 진단에 사용할 수 있지만 그 결과만으로 자연어 의미·규범 중복·소유권을 확정하지 않는다. 구조적 route 유일성은 기계 검사로, 규칙의 의미와 일반화는 상위 라우터가 선택한 규칙 거버넌스의 독립 감사로 판정한다. 실패 사건 문서는 예방책이나 사건 이력을 다시 소유하지 않는다.

## 4. 기록하지 않는 것

| 대상 | 이유 |
|---|---|
| 임시 실패 상태와 사건별 실패 서사 | §2의 Consumer 실행 구간에 한정된 임시 상태이며 재사용 지식이 아니다 |
| 미해결 차단의 시도 이력 | 현재 상태에는 원인·필요 결정·재시작 조건만 필요하다 |
| 거부된 승인 요청 | 예상된 안전 정지다 |
| 교정된 일회성 오타·인용 오류·옵션 실수 | 재사용 가치가 없다 |
| 복구된 일시적 도구 오류 | 재현되지 않으면 지식이 아니다 |
| 규칙에 흡수되고 테스트로 검증된 해결 사례 | 예방 소유자가 이미 재발을 막는다 |
| 같은 원인의 두 번째 문서 | 기존 예방 소유자를 갱신한다 |

실패의 원인이 아직 해결되지 않았으면 실패 지식으로 저장하지 않는다. 현재 작업을 재개하는 데 필요한 원인·필요 결정·재시작 조건과 실제 파일·Git 상태만 현재 상태에 유지하고, 해결되면 제거한다.

## 5. 조건과 행동

- **조건**: 현재 작업의 결과 시도가 실패한다.
  - **행동**: §2에 따라 원인·진전·남은 예산·외부 결과의 확정 여부를 확인하고 계속 또는 중단을 판정한다.
- **조건**: 해결되고 검증된 실패에 일반화된 Agent 판단·행동의 변경이 필요하다.
  - **행동**: §3에 따라 기존 규칙에 흡수하고 그 예방책을 검증한다.
- **조건**: 기존 예방 소유자와 같은 원인의 실패가 재발한다.
  - **행동**: §3의 분류에 따라 해당 기존 소유자를 보강한다. 구현에만 특정된 재발은 회귀 검사만 보강하고, Agent 판단·행동의 변경이 필요한 재발만 규칙을 보강한다.
- **조건**: 해결된 실패가 구현에만 특정되고 Agent의 판단·행동을 바꾸지 않는다.
  - **행동**: 기존 회귀 검사만 보강하고 활성 규칙을 바꾸지 않는다.
- **조건**: 실패의 원인이 아직 확인되지 않았다.
  - **행동**: 실패 지식으로 저장하지 않고 현재 차단과 재시작 조건만 유지한다.

## 6. 검증

- 명시된 예산 소진, 같은 원인의 무진전, 불명확한 외부 결과, 사용자 취소에서 후속 시도가 중단되는지 확인한다.
- 원인이 해소되고 권한·예산이 있는 새 시도와 충돌 없는 독립 진단은 허용되는지 대조한다.
- 하위 단계·Agent·동시 후보가 예산·권한·결과 충돌 경계를 우회하지 않는지 확인한다.
- 해결 사례의 일반화된 판단·행동이 활성 규칙 정확히 하나에만 있고 테스트·fixture가 규범 소유자가 되지 않았는지 확인한다.
- 구현에만 특정된 회귀 검사가 불필요한 활성 규칙을 만들지 않았는지 확인한다.
- 현재 상태와 핸드오프에 §2가 정의한 임시 실패 상태가 남지 않는지 확인한다.
