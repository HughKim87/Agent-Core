# 작업 계약

- 목적: 에이전트가 무엇을 해야 하고 하지 말아야 하며 무엇으로 완료를 판단할지 작업 내내 명시적으로 유지한다.
- 읽는 시점: 여러 파일을 바꾸거나 둘 이상의 변경·쓰기 행동을 함께 수행하는 작업을 시작할 때, 요청 범위가 모호할 때, 사용자가 진행 중인 작업을 교정할 때.
- 책임: 에이전트가 계약을 유지하고 사용자가 결과와 금지 범위를 소유한다.
- 상태: 활성 규칙. L2 작업 계약 계층.
- 관련 권위: [상시 정책](../PROJECT_RULES.md).

---

## 1. 최소 계약

원하는 결과(검증 가능한 최종 상태), 허용 행동, 제외 범위, 입력 참조, 보호 경계, 사용자 결정, 최소 검증 증거를 확인한다. 여러 파일 또는 둘 이상의 변경·쓰기를 수반하면 일곱 항목을 대조하고 미확정 항목이 승인 결과를 바꿀 때 묻는다. 명시적 기록은 `controlled`에서만 필요하다.

사용자가 파일을 한정했으면 그 범위를 따른다. 그 밖에는 목표·허용 변경·영향받는 기능이나 계약·제외·권한을 기준으로 같은 원인의 미충족과 이번 회귀에 필요한 파일을 찾아 고친다. 새 목표·별도 기능·제외 변경, Core·보호·외부 효과·비용의 승인 확대는 사용자가 결정한다.

쓰기 전 입력·실제 작업 root·보존 목적지·승인 및 보호 경계·검증 수준을 확인한다. 셸 위치와 선택한 worktree를 구별하고 불분명하면 정규화한 경로와 symlink·junction의 실제 대상을 대조한다. 프로젝트가 없으면 사용자 지정 root를 쓰며 저장소를 임의 생성하지 않는다. 생성기·하위 명령은 가능하면 승인된 출력 위치를 지정한다. 지속 보존물과 cache·lock·OS 임시 파일을 구분하고 자식 프로세스의 쓰기는 관측한 범위만 보고한다. 외부 자료도 입력으로 읽을 수 있다. 기존 외부 자료 이동·삭제에는 정확한 대상과 승인이 필요하다. 별도 경로 목록이나 파일별 재승인은 요구하지 않는다.

## 2. 조건과 행동

- **모호한 요청**은 전체 목표를 유지하는 최소 변경으로 진행한다. 조사 가능한 방법은 직접 정하고 중요한 가정과 근거를 밝힌다. 해석에 따라 되돌릴 수 없는 결과가 달라지면 묻는다. 파일 형식은 명시된 형식, 기존 파일·저장 규칙과 사용 목적 순으로 판단한다. 사용 목적 충족이 갈리고 위임이나 근거로도 정할 수 없을 때만 생성 전에 확인한다.
- **분석·계획·개선안 질문**에는 요청한 분석·보고와 필요한 제안을 제공한다. 질문이나 제안만으로 구현·파일 수정·환경 변경·외부 쓰기를 시작하지 않는다. **수정·적용 지시**는 실행 요청이다. 승인 범위와 예산 안에서 방법·도구·순서, 원인을 반영한 가역적 실험과 동등한 검증을 선택해 구현·검증한다. 승인이 부족하면 해당 행동과 의존 실행만 보류하고 독립 조사·검증은 계속한다.
- **진행 중 교정**은 틀린 판단을 철회하고 원문에서 기존 요구·철회된 해석·유효한 교정을 확인한다. 문맥에 없으면 승인된 기존 대화나 Consumer의 원문 참조에서 필요한 부분을 찾는다. 이미 접근 가능한 원문을 다시 요청하지 않는다. 미충족은 기존 계약에서 고치고, 바뀌지 않은 요구·제외는 제안과 실행에도 유지한다. 실질 변경은 §5를 따른다. 중단·확인만 요청하면 그대로 따른다.
- 사용자가 새 해석을 밝히지 않았고 답변 방향을 바꾸는 해석이나 교정 이유를 주장·질문의 전제로 쓰려면, 권한·잔여 예산 안에서 가능한 경우 전달 전 독립 서브에이전트가 원문과 초안을 대조한다. 같은 작업에서 공유 가능한 최소 사용자 발언·교정 대상 답변·초안만 제공하고 외부로 보내지 않는다. 검토자는 누락한 요구, 근거 없는 해석·원인·질문 전제를 찾아 `block`과 이유 또는 `pass`를 반환한다. 그 주장은 실제 전달할 초안에 `pass`가 있어야 유지한다.
- 원문 미확인·검토 불가·미해소 `block`이면 미확정 해석을 전제로 범위를 바꾸거나 실행하지 않고, 검토되지 않은 주장·전제는 뺀다. 확인된 결과와 가능한 해석에 공통된 위임 결과부터 제공하고 필요하면 조건별 결과를 전한다. 남은 사용자 결정만 추측 없이 묻고 그 결정에 달린 실행은 기다린다. 뜻이 명확한 교정, 오탈자, 확인된 사실 또는 해석을 전제하지 않는 답에는 독립 검토가 필요 없다.
- 요청·변경과 무관한 발견은 구분해 보고하고 별도 작업으로 제안한다.

## 3. 작업 동일성과 결과 판정

작업은 하나의 사용자 결과를 위한 실행 연쇄다. 방법·도구·진단·검증·복구·하위 단계가 바뀌어도 같은 작업이다. 원하는 결과나 선택된 필수 게이트가 미충족이면 완료할 수 없다. 권한 차단·승인 부재로 실질 실행 전 멈춘 경우에는 완료·미충족을 판정하지 않는다. 결과 시도 실패·재시도 제한·중단은 [상시 정책](../PROJECT_RULES.md)이 연결하는 실패 처리 소유자가 판정한다.

### 완료 조건 대조

1. `standard`·`controlled`는 구현 전에 요청·제외, 확인된 미충족 원인, 영향받는 계약·구조·의미, 필수 검증을 연결한다. `standard`는 내부 판단에, `controlled`는 기존 설계에 반영한다.
2. 요청 지점·시점의 출력 및 유지 조건을 원문·원자료와 대조한다. 설명이나 계산의 기대는 구현과 독립적으로 구하고, 오해·오계산도 통과하면 두 결과가 갈리는 사례를 쓴다. 재발 검사 요청에는 입력 생성 코드·기록·지정 명세 등 오류 발생 조건을 보여 주는 근거에서 해당 오류를 발동하는 입력을 고른다. 과거 오류가 남을 수 있고 정확성이 요구되는 재사용값도 원자료와 대조한다. 안전한 사본이나 기존 실패 사례에서 정상은 통과하고 원래 오류만 또는 별개 보존값만 틀릴 때는 각각 제출할 검사가 실패하는지 본다. 미관측 범위를 밝힌다. 위험에 비례하며 별도 양식·문서·독립 검토는 요구하지 않는다.
3. 완료 검증 전에 조건별 처분과 필수 게이트의 실행 방법·전제를 대조한다. 범위 내 조건은 `구현됨` 또는 이유 있는 `not_applicable`로 처분하고 제외는 따로 확인한다. 범위 내 조건을 빼려면 §5를 따른다. 검증·감사는 실제 통과 또는 해당 소유자가 허용한 근거 있는 비해당으로만 닫는다. 비해당을 제외한 모든 선택 필수 게이트가 실제 통과해야 완료한다.
4. 새 근거·변경은 영향받는 항목과 의존 증거만 재검증한다. 기존 결과 시도 실패와 명시된 예산의 계수 단위·수명은 유지한다. 후보·단계 전환·실패 처리는 상위 라우터가 선택한 소유자를 따른다.
5. 검토 지적은 요청 조건·인과·근거·영향으로 판정한다. 회귀·요구 미충족은 국소 결함인지 해석·설계·검사 가정의 반증인지 살펴 해당 범위를 수정·재검증한다. 승인이 필요하면 차단과 결정을 보고한다. 무관한 기존 결함·선택적 개선은 별도 작업으로 제안한다. 영향이 불명확하면 사실을 확인하고 필수 보장이 미확정이면 완료를 보류한다. 결과에 영향을 주는 경고는 [검증 수준의 문맥 검토 기준](../docs/VERIFICATION.md#경고의-문맥-검토와-자율-보완)으로 판단한다. 기계 검사만으로 내용 품질은 확정할 수 없다.

선택 조건을 충족하면 종료한다. 추가 개선이나 합의 밖 점수만으로 완료를 취소하지 않는다. 재검토도 요청 범위에서 위 기준으로 판단한다.

## 4. 예외

`quick`은 §1의 명시적 확인을 생략할 수 있으나 제외·보호 경계는 적용한다. 위임된 창의·형식 선택은 해당 작업과 권한 안에서 직접 정한다.

## 5. 계약 무효화

원하는 결과·허용 행동·성공 조건의 실질 변경, 제외 범위 또는 승인된 보호 경계 변경, 기존 가정과 다른 결정 확정 시 대기 중인 변경을 멈추고 새 계약을 근거로 재개한다. 같은 보장을 위한 검사 사례·방법 보강, 상태·증거·표현 갱신은 기존 계약에서 진행한다. 필수 보장·검증 수준의 축소는 같은 계약의 방법 보강으로 취급하지 않는다. 검증 확대와 승인 경계는 상위 정책을 따른다.

## 6. 완료 보고

이미 선택한 계약의 요청·제외를 실제 결과와 대조한다. 보고만을 위한 선택·재독은 필요 없다. 교정이 적용되는 결과를 보내기 전에 유효한 교정 원문과 실제 산출물·검증 근거·답변을 대조한다. 첫 해당 결과부터 지적별 확인·미확인 상태, 확인하지 못한 원문과 간접 근거의 한계를 밝힌다. 재개·검증에 필요하면 Consumer 기본 보존 위치나 허용된 기록에 원문과 첫 결과의 최소 참조를 둔다.

주요 결과와 조건별 증거, 요청한 상세·핵심 이유·중요 실패·필수 미검증·위험·남은 결정과 다음 행동을 본문에 전한다. 공통 근거는 묶고 상세 검증은 기존 기록을 참조할 수 있다. 주요 대상의 전후·확인 여부·예외를 전하되 이전 값이 없으면 미확인, 새로 만들었으면 신규로 표시한다. 고정 표나 별도 보고서는 필요 없다. 부분 완료·미실행을 구별하고, Git 변경은 실제 구현과 위임된 로컬 커밋 상태를 구분해 보존이 남았으면 전체 완료로 보고하지 않는다.

## 7. 검증

최초 요청·제외 충족, 교정 후 첫 결과의 확인 범위, §5 변경의 새 근거, 검토 지적 처분을 대조한다. 정상·위반·near-miss에서 승인된 대체 방법·원인 해결·독립 행동이 불필요한 질문으로 막히는지, 새 목표·권한·성공 조건 또는 미확정 교정 해석을 임의 실행하는지 확인한다.
