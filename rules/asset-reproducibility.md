# 대형 파일의 추적 제외와 워크플로우 재현

- 목적: 대형 파일의 불필요한 자동 추적을 줄이고, 제외한 입력과 결과를 새 작업 환경에서 검증된 방법으로 복원한다.
- 읽는 시점: 대형·대량 파일이 작업 범위에 들어오거나 Git·자동 추적에 새로 노출되기 전, 또는 해당 파일의 추적 범위·복원 방법이 바뀔 때. 기존 파일이 있는 작업 폴더의 Git 초기화와 자동 추적을 켜거나 범위를 넓히는 경우를 포함한다.
- 책임: Core는 판단·기록·검증의 공통 기준을 정한다. Consumer는 실제 경로·제외 설정·관리 문서와 워크플로우를 소유한다.
- 상태: 활성 규칙. L2 작업 계약 계층.
- 관련 권위: [상시 정책](../PROJECT_RULES.md)의 저장·승인·완료 경계.

## 1. 대상 분류와 제외

처음 파일을 쓰거나 추적에 노출하는 작업 전에 작업에 해당하는 경로를 확인한다. 크기, 파일 수, 변경 빈도, 추적 상태, 재설치·재생성 가능 여부와 원본의 고유성을 대조한다. 구체적인 조사 기준은 Consumer가 정한다. 상시 전체 탐색보다 필요한 경로의 목록과 파일 메타데이터를 우선한다.

- 제외하기로 한 대형 의존성과 생성물은 Consumer가 정한 좁은 경로에 두고, 추적 범위 안의 경로에 쓰기 전에 실제 제외 설정을 확인한다. 기존 승인 저장 경로와 도구가 관리하는 외부 저장소는 상시 저장 경계를 따른다. 다른 환경에도 필요한 제외는 Consumer가 버전 관리하는 설정으로 유지한다. 재현에 필요한 파일의 장비 전용 예외는 Consumer가 복원 방법을 기록한다.
- 기존 추적 파일은 ignore 추가만으로 제외됐다고 판정하지 않는다. 현재 원본과 추적 상태를 확인하고, 변경이 필요하면 복원 위치와 영향 범위를 명시해 승인된 범위에서 별도로 처리한다. 고유 원본은 검증된 보관·복원 근거를 확보하기 전까지 기존 보존 방식을 유지한다.
- 기존 파일이 있는 폴더를 새 저장소로 만들 때는 초기 커밋에 넣을 파일뿐 아니라 자동 추적에 포함될 수 있는 미추적 대형 파일도 확인한다. 공통 확장자나 상위 제작 폴더 전체로 제외 범위를 넓히기 전에 필수 입력·고유 원본과의 경계를 확인한다.

기존 환경에서 모델과 추적 범위를 그대로 사용하거나, 프로젝트 밖의 추적되지 않는 설치 환경만 갱신하거나, 일반 소형 파일을 편집할 때는 이 규칙만으로 탐색이나 관리 문서 갱신을 요구하지 않는다. 이 규칙은 설치, 외부 전송, 파일 이동·삭제, Git 이력 변경의 권한을 부여하지 않는다.

## 2. 프로젝트 관리 기록

제외한 파일이 워크플로우 실행·결과 검증·고유 원본 복원에 필요하면 Consumer의 관리 문서 또는 연결된 기존 정본에 공통 제외·복원 정보를 남긴다. 워크플로우와 기준 출력 항목은 해당 실행·결과 검증에 필요한 경우에 추가한다. Consumer Extension을 사용하는 경우 프로젝트별 발동 조건과 관리 문서 진입·갱신 경로를 Extension에 두고, 실제 값은 Consumer 정본에서 관리한다. 별도 Extension 파일이나 중복 목록을 일률적으로 요구하지 않는다.

| 항목 | 최소 내용 |
|---|---|
| 제외 기준 | 상대 경로 또는 정확한 패턴, 파일 역할과 이유, 공유 또는 로컬 적용 범위 |
| 설치·복원 | 모델·도구 식별자와 고정 리비전·버전 또는 백업 식별값, 출처·설치 위치·복원 방법, 무결성 확인 근거 |
| 워크플로우 | 입력 식별값, 실행 절차와 정의의 revision, 출력에 영향을 주는 설정·환경 |
| 기준 출력 | 해당하는 경우 기준 출력의 위치·식별값과 비교 기준 |
| 검증 | 적용되는 검증별 결과·근거, 검증 환경과 시점 |

복원에 필요한 값이 빠졌으면 접근이 허용된 잠금 파일·모델 목록·설치 설정·실행 정의·관측 기록 등 기존 근거를 먼저 대조하고 해당 정본을 참조한다. 그 범위에서 확인하지 못한 값은 확인한 출처와 그 값이 필요한 판단 또는 실행을 함께 기록한다. 경로·버전·입력·워크플로우·기준 출력이 바뀌면 영향을 받는 기록과 검증만 갱신한다. 복원이나 실행에 필요 없는 일회성 캐시는 공통 제외 범위와 이유만 유지할 수 있다.

## 3. 검증과 완료

변경된 범위와 요청된 완료 수준에 해당하는 검증을 고른다. 의도적으로 추적을 유지하는 항목에는 제외 검증을 요구하지 않는다. 초기화만 하거나 복원 경로·실행 환경·결과에 영향이 없는 변경에는 전체 워크플로우 재실행을 요구하지 않는다.

설치·재취득 문서의 충분성, 고유 원본의 원위치 보존, 원본 손실 후 복원, 새 환경의 실제 실행 결과는 각각 해당하는 근거로 판정한다. 원위치 보존을 선택한 경우 승인 범위에서 보존·참조 방법과 손실 시 복원 한계를 기록한다. 별도 보관본의 부재는 그 원본의 손실 복원에 반영하고, 독립적으로 검증할 수 있는 문서의 완료 조건에 추가하지 않는다. 동일 원본 복원을 요청받으면 복원한 파일과 원본의 동일성을 검증한다. 결과 재현을 요청받으면 아래 결과 재현 검증을 통과해야 그 결과가 완료된다. 각 검증의 기준은 다음과 같다.

1. **Git 제외** — Git 저장소에서 제외하는 대상이 인덱스에 남아 있지 않고 실제 미추적 수집 후보에서도 빠지는지 확인한다. 보호 범위와 기존 작업이 보존됐는지 대조한다.
2. **자동 추적 제외** — 이를 사용하는 앱에서 해당 자동 스냅샷의 대상 목록이나 그 동작을 직접 관측할 수 있는 증거로 제외를 확인한다. Git 제외 판정만으로 앱 검증을 통과시키지 않는다.
3. **결과 재현** — 기존 설치·캐시·미기록 로컬 설정에 의존하지 않는 새 환경에서 기록만 따라 필요한 파일을 복원하고, 대표 입력으로 실제 워크플로우를 끝까지 실행해 기준 출력과 대조한다. 고유 원본의 동일 파일 복원이 요구되면 보관본도 검증한다.

출력이 바이트 단위로 동일해야 하면 기준 해시와 비교한다. 실행 환경에 따라 바이트가 달라질 수 있는 출력은 요구에 맞는 비교 기준을 미리 정하고 실제 차이를 기록한다. 모델 로드 성공이나 허용 오차 통과를 바이트 일치로 보고하지 않는다. 검증별로 `pass`, `fail`, `not_run` 또는 근거 있는 `not_applicable`을 기록하며, 관측하지 못한 자동 추적 제외·환경 재현·성능 개선을 완료로 주장하지 않는다.
