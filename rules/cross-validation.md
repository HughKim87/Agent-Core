# 교차검증

- 목적: 여러 Agent·보고서·분석의 결론을 비교할 때 출처 공유를 독립 검증으로 과장하지 않고 현재 근거에 따라 판정한다.
- 읽는 시점: 다른 Agent의 보고서를 검토하거나, 둘 이상의 분석을 교차검증·통합하거나, 독립 재현 여부를 주장할 때.
- 책임: 에이전트가 주장별 출처·검증 방법·현재 상태를 분리하고, 사용자가 최종 판단과 추가 검증 범위를 정한다.
- 상태: 활성 규칙. L2 검증 계층.
- 관련 권위: [상시 정책](../PROJECT_RULES.md), [검증 수준](../docs/VERIFICATION.md).

---

## 1. 근거 등급

물질적 주장마다 다음 중 하나를 표시한다.

| 등급 | 의미 |
|---|---|
| 직접 재측정 | 현재 검토자가 기본 파일·명령·테스트에서 결과를 다시 확인 |
| 독립 재현 | 서로 다른 방법이나 독립 실행이 같은 결과에 도달 |
| 공통 출처 일치 | 여러 분석이 같은 파일·보고서·측정값을 근거로 동의 |
| 보고됨·미검증 | 출처에는 있으나 현재 검토자가 재현하지 않음 |

공통 출처의 반복 인용, 복제된 보고서, 같은 transcript의 재서술은 독립 근거 수를 늘리지 않는다.

## 2. 검토 절차

1. 현재 검토자, 원 보고서 작성자, Runtime, 작성·검사 시점을 분리한다.
2. 결론보다 기본 파일·실행 결과·공식 계약을 먼저 확인한다.
3. 저장소 상태처럼 변하는 주장은 검사 시점, branch 또는 revision, 관련 경로를 함께 기록한다.
4. 주장별로 일치, 불일치, 미확인을 구분하고 불일치의 원인이 범위·시점·방법 중 무엇인지 확인한다.
5. 두 보고서를 합칠 때는 결론, 근거 등급, 이견, 미해결 위험만 보존하고 서사를 중복 복사하지 않는다.

현재 세션은 출처 보고서의 Agent 이름·역할·정체성을 상속하지 않는다. 다른 Agent의 자기보고는 실행 결과와 별개 증거다.

## 3. 경계

- 현재성·보안·권한·가격·버전·API처럼 변할 수 있는 사실은 가능한 경우 공식 또는 기본 출처에서 다시 확인한다.
- 반대 증거가 없다는 사실을 확인으로 바꾸지 않는다.
- 신뢰도를 높인다는 이유로 보호 데이터·비밀·승인 밖의 경로에 접근하지 않는다.
- 보고만 요청받았으면 교차검증은 규칙 변경, 구현, sidecar 문서, 외부 쓰기를 승인하지 않는다.
- 합성 fixture와 실제 프로젝트 재현, 구조 일치와 행동 일치를 구분한다.

## 4. 검증

- 모든 물질적 결론이 안전한 출처와 근거 등급에 연결되는지 확인한다.
- 동일한 출처가 독립 증거로 중복 계수되지 않았는지 확인한다.
- 정체성, 날짜, revision, 동적 수치를 최종 보고 직전에 다시 확인한다.
- 모순과 미검증 주장이 명시되어 있고 추론이 직접 측정으로 표현되지 않았는지 확인한다.
- 요청한 산출물과 권한 범위를 넘는 변경이 없는지 확인한다.
