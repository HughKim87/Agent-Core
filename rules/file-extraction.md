# 파일 지식 추출과 출처 보존

- 목적: 파일·저장소를 합치거나 정리하기 전에 재사용할 지식과 프로젝트별 사실을 분리하고, 각각을 정본 소유자와 원래 출처에 연결한다.
- 읽는 시점: 파일에서 규칙·실패 예방책·현재 상태·근거·출처를 추출하거나, 병합·정리·삭제·이동 전에 고유 내용을 판정할 때. 활성 규칙 자체의 추가·통합과 일반 내용 요약은 제외한다.
- 책임: 에이전트가 최소 범위를 읽고 분류·소유권·출처를 제시하며, 사용자가 새 정본과 Core 범위 변경을 승인한다.
- 상태: 활성 규칙. L2 작업 계약 계층.
- 관련 권위: [상시 정책](../PROJECT_RULES.md), [정보 소유 구조](../docs/INFORMATION_ARCHITECTURE.md).

---

## 1. 추출 전 범위 고정

추출하기 전에 다음을 고정한다.

| 항목 | 내용 |
|---|---|
| 원본 | 읽을 정확한 파일·저장소·revision |
| 목적 | 병합, 이전, 규칙 개선, 정리 후보 판정 등 이번 추출의 사용처 |
| 허용 범위 | 읽기·쓰기 대상과 제외 경로 |
| 결과 독자 | Core Maintainer, 특정 Consumer, 현재 작업 등 |
| 보존 owner | 추출 결과가 들어갈 기존 정본 또는 보류 owner |

선언된 보호 경로는 정확한 항목과 목적 승인 없이 열거하거나 읽지 않는다. 원본 질문에 직접 필요하지 않은 형제 파일과 과거 이력을 편의상 넓게 읽지 않는다.

## 2. 분류

추출한 각 항목은 다음 중 정확히 하나로 분류한다.

| 분류 | 기본 소유 |
|---|---|
| 도메인 중립의 반복 가능한 조건·행동 | 가장 좁은 기존 Core 규칙 후보 |
| 프로젝트·도메인별 조건·행동 | 해당 Consumer 규칙 |
| 현재 단계·차단·첫 다음 행동 | 해당 Consumer의 현재 상태 |
| 검증된 일반 실패의 예방책 | 기존 규칙 또는 결함 주입 검사 |
| 원본 저장소·revision·경로와 변환 관계 | 해당 Consumer의 source lineage owner 또는 원래 Git |
| 단일 작업의 수치·파일명·해시·승인 | 현재 작업의 근거 owner |
| 완료 과정·과거 제안 | Git 이력 또는 한시 참고 자료 |
| 재생성 가능하고 고유 판단이 없는 파생물 | 정리 후보 |

분류되지 않은 항목을 공통 규칙이나 폐기 대상으로 추측하지 않는다.

## 3. 일반화와 흡수

1. 기존 정본을 먼저 찾는다. 같은 책임의 새 문서를 만들지 않는다.
2. Core 후보에서는 프로젝트명·도메인 어휘·고정 경로·일회성 수치를 제거하고 관측 가능한 `조건 / 행동 / 예외 / 검증`으로 표현한다.
3. 프로젝트별 상태·도메인 규칙·데이터·보호 경로는 Core로 승격하지 않는다.
4. 규칙 후보는 규칙 변경 절차에서 trigger·owner·route·fixture를 별도로 검증하기 전까지 활성 규칙이 아니다.
5. 반복 근거가 부족하거나 owner가 확정되지 않은 항목은 새 정본을 자동 생성하지 않고 보류 이유와 원본 위치를 남긴다.
6. 추출만 요청받았으면 삭제·이동·이름 변경을 실행하거나 예약하지 않는다.

## 4. 여러 출처의 병합

- 서로 다른 프로젝트의 자료를 같은 위치에 합치기 전에 원본 저장소, revision 또는 동등한 불변 식별자, 원래 상대경로를 복원할 수 있어야 한다.
- 동일해 보이는 항목도 정본·파생물·독립 근거를 판정하기 전에는 하나로 세지 않는다.
- 병합된 자료의 실제 내용은 Consumer가 소유한다. Core는 공통 절차와 검증 기준만 소유한다.
- source lineage는 정본 흡수와 의존 해제가 검증되기 전에 제거하지 않는다. 원래 Git 이력만으로 동일한 출처를 복원할 수 있으면 별도 복제 문서를 만들지 않는다.

## 5. 역사 자료

과거 보고서·구현·삭제된 규칙을 읽을 때는 확인할 질문과 exact path를 먼저 정한다. 역사 자료는 현재 권위가 아니라 근거다. 결과는 `확인된 과거 사실`, `현재 적용 가능성`, `새 추론`으로 분리한다.

## 6. 검증

- 추출 항목마다 분류, 원본, 정본 owner, 흡수·보류·미추출 이유가 있는지 확인한다.
- Core로 흡수한 항목에 프로젝트별 이름·경로·데이터가 남지 않았는지 확인한다.
- source lineage 없이 서로 다른 프로젝트 자료가 합쳐지지 않았는지 확인한다.
- 보호 데이터·비밀·사용자 원본이 규칙·보고서·fixture·커밋에 복제되지 않았는지 확인한다.
- 추출 결과가 기존 정본과 중복되지 않고, 새 활성 규칙은 유일한 route와 의미 fixture를 갖는지 확인한다.
