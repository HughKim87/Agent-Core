# 문서 작업

- 목적: 필요한 문서만 만들고 오래된 문서와 중복 정본이 활성 트리에 쌓이지 않게 한다.
- 읽는 시점: 일반 유지 문서를 만들거나 바꿀 때, 보고서·계획·설계 문서를 요청받았을 때, 작업 종료 시 임시 문서를 처분할 때. 활성 규칙·현재 상태·실패 예방·파일 추출의 전용 소유권 판정은 제외한다.
- 책임: 에이전트가 문서 배치를 유지하고 사용자가 새 정본의 추가를 승인한다.
- 상태: 활성 규칙. L2 작업 계약 계층.
- 관련 권위: [상시 정책](../PROJECT_RULES.md), [정보 소유 구조](../docs/INFORMATION_ARCHITECTURE.md)가 정본 위치를 소유한다.

---

## 1. 문서의 목적과 범위

문서는 작업의 결과와 필요한 근거를 남기는 수단이다. 요청·위임 범위 밖의 유지 보고서·계획서·README나 중복 정본을 만들지 않는다. 별도 관리·저장·배포·갱신 책임을 갖는 산출물은 형식과 관계없이 같은 범위 판정을 받는다.

승인된 답변의 일회성 표·차트·설명과 작업 수행에 필요한 설계·검증·재개 근거는 그 요청 범위에서 선택할 수 있으며 표현이나 파일 형식만으로 새 승인을 요구하지 않는다. 새로운 유지 정본·독립 산출물·외부 쓰기의 승인으로 확대하지 않는다. 요청 범위 밖의 유지 산출물이 필요하면 결과와 필요를 제안한다.

`quick`과 `standard` 작업은 기존 소유자·응답·커밋으로 충분하면 별도 문서를 만들지 않는다.

## 2. 문서 생성 게이트

새 유지 문서를 만들기 전에 다음을 확인한다. 기존 소유자가 목적을 충족하면 그 소유자를 갱신하고, 필요한 판단이 불명확하면 새 정본 생성만 보류한다.

1. [정보 소유 구조](../docs/INFORMATION_ARCHITECTURE.md)에서 이 정보 유형의 기존 정본을 찾는다.
2. 기존 정본이 이 목적을 충족하지 못하는 이유를 한 문장으로 설명한다.
3. 정보 유형과 계층을 각각 하나씩 정한다.
4. 포함 정보와 금지 정보를 정하고 기존 정본을 복제하지 않는지 확인한다.
5. 갱신 책임과 종료 조건을 정한다.
6. 기존 정본의 갱신이나 파생 표현으로 충분하면 만들지 않는다.

전체 파일 목록을 별도 정본으로 유지하지 않는다. 필요한 탐색은 개요·정본·Git 검색을 사용하고 특정 검증의 대상 목록은 해당 근거와 구분해 식별한다.

문서의 논리적 정본 소유자와 실제 보존 위치를 함께 확인한다. 보고서·분석·검증 근거의 목적지는 상시 정책의 프로젝트 산출물 저장 경계를 따르며, Git clean을 위해 외부로 돌리지 않는다. 외부 도구의 임시 결과를 보존 자료로 사용할 때는 내부 또는 승인된 보존 위치에 남기고 활성 링크·재개 참조도 그 위치와 일치하는지 완료 전에 확인한다. 출처의 과거 경로 기록은 활성 링크와 구분하며 기존 외부 원본의 이동·삭제를 자동 수행하지 않는다.

## 3. 최소 문서 설명

새로 만들거나 책임이 바뀌는 유지 문서는 다음 다섯 정보를 명확히 제공한다.

- 목적
- 읽는 시점
- 책임
- 상태
- 관련 권위

일반 유지 문서에는 특정 제목·순서·언어·리터럴을 강제하지 않는다. 표나 본문으로 같은 정보를 충분히 제공하면 유효하며, 기존 문서를 일괄 변환하지 않고 실제 수정 시 부족한 정보만 보완한다. 기계 검사는 누락 가능성을 진단하고 의미 충분성은 문맥에서 확인한다. 활성 규칙 등 전용 소유자가 정한 기계 계약은 해당 계약을 따른다.

## 4. 읽기 예산과 정보 충분성

구성된 소비 저장소의 시작 문맥은 Core 정책, 소비 정책, 소비 상태 세 문서다. 여기에 현재 작업에 일치하는 Core·소비 규칙만 더한다.

- 문서의 충분성·최신성·중복으로 품질을 판단한다. 길이만으로 실패·분할·삭제를 결정하거나 필요한 승인·제약·위험·결정 근거를 생략하지 않는다.
- 문서나 필수 읽기 문맥의 증가는 중복·책임 혼합·불필요한 완료 상세가 있는지 검토하는 신호다. 같은 책임의 필요한 내용이 늘었다면 유지할 수 있다.
- 실제 실행 환경이나 작업 계약에 명시된 용량·비용 예산은 지킨다. 예산을 맞출 수 없으면 필요한 근거를 감추지 않고 소유권·라우팅·표현 개선 또는 예산 결정을 제시한다.

## 5. 조건과 행동

- **조건**: 사용자가 보고서나 요약 문서를 요청하지 않았다.
  - **행동**: 응답·기존 소유자·커밋으로 충분하면 별도 유지 보고서를 만들지 않는다. 실행·검증·재개에 필요한 최소 근거는 해당 작업의 범위와 소유 위치에서 보존한다.
- **조건**: 같은 책임의 활성 문서가 이미 있다.
  - **행동**: 새로 만들지 않고 기존 소유자를 갱신한다.
- **조건**: 작업 전용 임시 문서를 만들었다.
  - **행동**: 종료 조건에 따라 검증된 내용은 정본에 흡수하고 남은 정보의 재개·검증 가치를 판정한다. 가치 없는 과거와 중복 때문에 전체를 남기지 않으며 물리적 처분은 적용되는 승인 경계를 따른다.
- **조건**: 완료 과정의 정보가 다음 판단이나 검증에 필요하다.
  - **행동**: 완료 이력은 Git에 남기고 현재 유효한 결정·제약·검증 증거만 해당 소유자에서 식별한다. 전체 과정이나 정책 원문을 별도 문서로 중복 복제하지 않는다.

## 6. 예외

- 사용자가 명시적으로 요청한 문서는 이 규칙의 생성 제한을 받지 않는다. 단 §2의 4번과 §3은 여전히 적용된다.
- 한시 참고 자료는 정본이 아니며 검증·재개 근거로 참조하더라도 현재 정책·상태의 별도 정본으로 사용하지 않는다. 종료 조건을 명시하고 유지한다.

## 7. 검증

- 유지 산출물은 사용자 요청·위임 범위와 대조하고, 일회성 답변·필요한 검증 근거·새 유지 정본을 구분하는지 확인한다.
- 새 문서 요청을 기존 소유자 갱신과 신규 생성으로 판정한 근거가 있는지 확인한다.
- 중복 소유자, 고아 문서, 깨진 링크를 검사한다.
- 일반 유지 문서가 §3의 다섯 정보를 의미상 제공하는지 확인하고 형식 경고를 확정 위반으로 확대하지 않는다.
- 작업 종료 후 임시 문서의 남은 가치·소유자·종료 조건이 명확한지 확인한다.
