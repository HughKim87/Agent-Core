# 보호 데이터와 외부 효과

- 목적: 사용자 원본, 비밀정보, 외부 서비스 변경을 명시적 권한 밖에서 접근하거나 실행하지 않게 한다.
- 읽는 시점: 보호 경로의 항목을 다룰 때, 비밀이 있을 수 있는 파일을 다룰 때, 외부 서비스에 영향을 주는 행동을 하기 전.
- 책임: 사용자가 접근 대상과 목적을 승인하고 에이전트가 경계를 지킨다.
- 상태: 활성 규칙. L2 작업 계약 계층.
- 관련 권위: [상시 정책](../PROJECT_RULES.md) §6·§7이 상위다.

---

## 1. 보호 대상

| 종류 | 정의 |
|---|---|
| 보호 경로 | 사용자 원본과 결과물이 있는 선언된 경로 |
| 비밀 | 자격 증명, 토큰, 쿠키, 브라우저 프로필, 비밀번호, 개인 키, API 키 |
| 외부 효과 | 저장소 밖의 상태를 바꾸는 모든 행동 |
| 참고 구현 | 읽기 전용으로 선언된 외부 저장소 |

보호 경로의 정확한 목록은 각 저장소가 선언한다. Core는 그 선언을 조회하며 이름을 하드코딩하지 않는다.

## 2. 접근 전 차단

정확한 대상과 목적이 승인되기 전에는 다음을 하지 않는다.

- 열거와 목록 조회
- 읽기
- 색인과 검색 대상 포함
- 링크와 참조 생성
- Git 스테이지와 커밋

**열거가 읽기보다 앞선다.** 디렉터리 목록만 가져오는 것도 보호 데이터의 존재와 이름을 노출한다. 승인 없는 재귀 탐색은 읽기와 같은 취급이다.

## 3. 조건과 행동

- **조건**: 작업이 보호 경로 안의 항목을 필요로 한다.
  - **행동**: 정확한 대상과 목적을 사용자에게 확인한 뒤에만 접근한다. 승인된 항목 외의 형제 항목을 함께 읽지 않는다.
- **조건**: 파일에 비밀이 있을 수 있다.
  - **행동**: 읽지 않는다. 값이 필요하면 사용자에게 주입 방법을 요청한다. 비밀을 로그·오류·보고서·컨텍스트에 남기지 않는다.
- **조건**: 행동이 외부 상태를 바꾼다.
  - **행동**: 로컬 분석과 외부 쓰기를 분리한다. 외부 쓰기는 정확한 대상 승인 전에 실행하지 않는다.
- **조건**: 외부 변경 중 예상하지 않은 물질적 손상이나 상태 불일치가 확인됐다.
  - **행동**: 영향받은 범위의 남은 외부 쓰기·개선·확대를 즉시 중단하고, 추가 쓰기 없이 확인된 영향과 미확정 범위를 구분해 사용자에게 보고한다. 기존 승인을 사고 이후의 재개·복구 승인으로 간주하지 않는다. 사용자가 확인된 영향과 선택지를 바탕으로 결정하고 선택된 결과 확인이 통과한 뒤에만 재개한다.
- **조건**: 외부 변경이 되돌리기 어렵거나 외부 객체의 정체성·이력에 영향을 준다.
  - **행동**: 승인을 요청하기 전에 확인된 영구 손실, 복구되는 범위와 복구되지 않는 범위, 확인하지 못한 복구 가능성, 목적을 충족하는 가역적 대안을 사용자에게 제시한다. 확인하지 못한 복구 능력을 사용할 수 있는 것으로 표현하지 않으며, 사용자가 이 정보를 바탕으로 승인한 뒤에만 실행한다.
- **조건**: 도구가 보호 경로를 자동으로 포함할 수 있다.
  - **행동**: 도구 호출 전에 제외를 명시한다. 사후 필터링에 의존하지 않는다.

## 4. 복제 금지

보호 데이터의 내용은 다음으로 옮겨지지 않는다.

- 유지 문서
- 로그와 오류 메시지
- 컨텍스트 패키지
- 테스트 fixture
- 커밋

오류 메시지가 보호 경로의 내용을 노출하지 않도록 경로만 보고하고 내용을 인용하지 않는다.

## 5. 예외

- 사용자가 정확히 지목한 항목은 그 목적 범위 안에서 읽고 다룰 수 있다.
- 보호 경로의 존재 여부 자체를 확인해야 하는 검증은 내용을 읽지 않고 경로 수준에서만 수행한다.
- 참고 구현은 읽을 수 있으나 어떤 경우에도 쓰지 않는다. 읽기조차 부작용을 남기는 실행은 사본에서 한다.

## 6. 검증

- 보호 경로에 대한 직접 접근, 재귀 탐색, 링크, Git 추적 시도를 각각 검사한다.
- 외부 변경 요청이 승인 전 단계에서 정지하는지 확인한다.
- 외부 손상 확인 뒤 새 사용자 결정과 결과 확인 전에 영향받은 범위의 추가 외부 쓰기·개선·확대가 실행되지 않는지 확인한다.
- 비가역 외부 변경이 영구 손실·복구 한계·미확인 항목·가역적 대안을 제시하기 전에 승인 요청 또는 실행으로 넘어가지 않는지 확인한다.
- 오류 메시지와 보고서가 보호 내용을 노출하지 않는지 확인한다.
- 참고 구현 트리에 부작용 파일이 생기지 않았는지 확인한다.
