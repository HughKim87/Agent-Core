# 현재 상태와 세션 인수인계

- 목적: 소비 저장소의 다른 에이전트나 새 세션이 대화 없이 정확한 중단 지점부터 재개하게 한다.
- 읽는 시점: 작업을 중단·인계하거나 소비 저장소의 현재 상태를 갱신할 때.
- 책임: 작업 에이전트가 선언된 상태를 갱신하고 사용자가 승인 상태를 소유한다.
- 상태: 활성 규칙. L2 작업 계약 계층.
- 관련 권위: [Core 상시 정책](../PROJECT_RULES.md), 소비 저장소의 `agent-core-consumer:v1` 선언.

---

## 1. 상태 정본 찾기

현재 상태의 경로는 Core에 고정하지 않는다. 소비 저장소 정책의 소비 계약 선언에서 `state` 값을 읽고 소비 root 안쪽의 상대경로로 해석한다.

Core 저장소 자체는 현재 상태를 소유하지 않는다. Core 변경 작업의 상태는 `maintainer` 소비 저장소가 소유한다.

## 2. 상태 문서 계약

상태 문서는 다음 절을 갖는다.

| 절 | 내용 |
|---|---|
| 현재 단계 | 주 진입단계, 활성 설계, 재개에 필요한 독립 활동의 소유자·범위·의존 조건·검증 상태 |
| 직전 게이트 | 바로 앞 판정 하나와 완료 수준을 식별하는 근거 |
| 승인 상태 | 현재 유효한 결정·위임·제외 범위 |
| 차단 | 현재 원인, 필요한 결정, 재시작 조건 |
| 알려진 위험 | 미검증 항목과 해소 시점 |
| 첫 다음 행동 | 번호가 매겨진 구체적 행동 |

상태는 재개에 충분한 최신 정보를 담는다. 3천자는 중복·완료 상세 누적을 살피는 검토 신호이며 초과 자체는 실패가 아니다. 필요한 승인·제약·반증 원인·위험을 분량에 맞춰 생략하지 않는다. 별도로 명시된 실행 환경·작업의 용량·비용 예산은 유지한다.

## 3. 보존과 제외 기준

다음 판단·재개·검증을 바꾸는 현재 유효한 결정, 제약과 확인된 실패·반증 원인은 보존한다. 사용자의 승인·제외 범위는 현재 계약으로 정리하며 대화의 순서를 재현하지 않는다.

다음은 포함하지 않는다.

- 재개 판단에 필요 없는 완료 과정과 과거 판정 전체
- 현재값처럼 고정한 동적 Git 수치와 파일 개수
- 정책·규칙 본문과 대화 원문·서사
- submodule gitlink를 대신하는 현재 Core 배포 revision 정본
- 상시 정책 route가 선택한 실패 처리 소유자가 정의한 임시 실패 상태

중간 보존 지점과 완료 이력은 해당 저장소의 Git commit이 소유한다. 미완성 체크포인트와 검증된 복구 기준점은 구분한다. 전체 단계 작업 종료 보고서는 결과 요약을 소유하며 현재 상태에는 그 참조·최종 판정·남은 행동만 남겨 완료 과정을 중복하지 않는다. 특정 검증의 snapshot revision·hash는 당시 검증 대상을 식별하는 근거로 보존하거나 참조할 수 있으며 현재 배포 revision을 선언하는 용도로 사용하지 않는다.

## 4. 조건과 행동

- 단계나 독립 활동이 전환되면 현재 단계, 직전 게이트, 승인 상태, 첫 다음 행동을 갱신한다.
- 작업을 중단하면 다음 사람이 실행할 첫 행동과 필요한 결정·제약·차단·검증 근거를 기록한다.
- 차단이 생기면 시도 이력 대신 현재 원인·필요 결정·재시작 조건을 기록한다. 다른 방법의 선택을 바꾸는 확인된 반증은 보존한다.
- 미커밋 변경·로컬 전용 입력에 의존하면 `same-workspace`로 표시한다. `portable`은 필요한 고정 내용과 연결된 Core snapshot을 수신 환경에서 실제로 확보해 복원할 수 있을 때만 사용한다. Git 추적 여부만으로 충분하지 않으며 미커밋 tracked 내용과 로컬에만 있는 commit은 전달 경로 확인 없이 portable로 표시하지 않는다.
- `quick` 작업은 상태를 갱신하지 않는다.

## 5. 첫 다음 행동

- 실행할 행동과 대상 파일·명령·판정 조건을 구체적으로 적는다.
- 언어·문체·종결어미보다 새 에이전트가 실행 가능한 대상을 식별할 수 있는지로 판단한다.
- “계속 진행한다”, “검토한다”, “확인한다”처럼 행동이나 대상이 정해지지 않은 표현만 적지 않는다.

## 6. 검증

- 선언된 상태 경로가 소비 root 밖으로 나가지 않는지 검사한다.
- 필수 절·선언 형식의 기계 검사와 길이·동적 수치·첫 행동 구체성의 문맥 검토를 구분한다. 정규식 일치·불일치와 길이만으로 의미 규칙 전체의 준수나 위반을 확정하지 않는다.
- 새 에이전트가 Core 정책·소비 정책·상태만으로 목표·승인·제약·차단·다음 행동을 재진술하게 한다.
- 합성 구조 통과와 실제 cross-agent 재개를 구분해 보고한다.
- 현재 유효한 근거는 보존하고 §3의 불필요한 서사·중복 정본이 남지 않는지 확인한다.
