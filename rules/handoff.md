# 현재 상태와 세션 인수인계

- 목적: 대화 기록 없이 다른 에이전트나 새 세션이 정확한 중단 지점부터 작업을 재개하게 한다.
- 읽는 시점: 작업을 중단하거나 넘길 때, 현재 상태 문서를 갱신할 때, 재개 가능성을 판정할 때.
- 책임: 에이전트가 상태를 갱신하고 사용자가 승인 상태를 소유한다.
- 상태: 활성 규칙. L2 작업 계약 계층.
- 관련 권위: [상시 정책](../POLICY.md), [정보 소유 구조](../docs/INFORMATION_OWNERSHIP.md)가 정본 위치를 소유한다.

---

## 1. 현재 상태 문서의 계약

현재 상태 문서는 `STATE.md` 하나다. 다음 절을 갖는다.

| 절 | 내용 |
|---|---|
| 현재 단계 | 활성 단계, 활성 전체 설계, 활성 단계 설계 |
| 직전 게이트 | 바로 앞 단계의 판정 하나. 그 이전은 Git이 소유한다 |
| 승인 상태 | 위임된 것과 위임되지 않은 것 |
| 차단 | 지금 진행을 막는 것. 없으면 없다고 적는다 |
| 알려진 위험 | 미검증 항목과 해소 시점 |
| 첫 다음 행동 | 번호가 매겨진 실행 가능한 행동 |

통과 이력 전체를 표로 누적하지 않는다. 그렇게 하면 문서가 단계 수에 비례해 커진다. 실측에서 이 누적이 실제로 발생해 문서가 19단계 동안 약 1.8배로 커졌다.

## 2. 포함하지 않는 것

| 제외 | 이유 |
|---|---|
| 완료된 단계의 상세 과정 | Git 커밋이 소유한다 |
| 과거 판정의 근거 서술 | 해당 단계의 커밋과 계약 문서가 소유한다 |
| 동적 Git 수치와 파일 개수 | 실행 조회로 얻는다. 문서에 고정하면 어긋난다 |
| 정책·규칙 본문 | 각 소유자가 소유한다 |
| 대화 내용과 사용자의 발언 요약 | 재개에 필요한 결정만 승인 상태에 남긴다 |

현재 상태 문서의 크기는 진행한 단계 수와 무관하게 일정해야 한다. 단계를 진행할수록 커진다면 §2를 위반하고 있는 것이다.

## 3. 조건과 행동

- **조건**: 단계가 전환된다.
  - **행동**: 현재 단계, 통과한 게이트, 첫 다음 행동을 갱신하고 완료된 단계의 상세를 제거한다.
- **조건**: 작업을 중단한다.
  - **행동**: 중단 시점의 첫 다음 행동, 승인 상태, 금지 사항을 기록한다. 무엇을 하려다 멈췄는지가 아니라 다음 사람이 무엇부터 해야 하는지를 쓴다.
- **조건**: 차단이 발생한다.
  - **행동**: 차단 원인, 시도한 방법, 필요한 결정을 기록한다. 차단을 첫 다음 행동으로 위장하지 않는다.
- **조건**: 재개 조건이 현재 workspace에 의존한다.
  - **행동**: §4에 따라 재개 방식을 명시한다.

## 4. 재개 방식의 구분

| 방식 | 조건 | 명시 사항 |
|---|---|---|
| `same-workspace` | 추적되지 않는 로컬 상태나 임시 파일에 의존한다 | 그 상태가 이 workspace에만 있다는 사실 |
| `portable` | 저장소의 추적된 내용만으로 재개된다 | 없음 |

실제로 복구할 수 없는 상태를 `portable`로 표시하지 않는다. 과장된 재개 가능성은 다음 세션의 시간을 소모시키고 신뢰를 떨어뜨린다.

## 5. 첫 다음 행동의 형태

- 실행 가능한 동사로 시작한다.
- 대상 파일이나 경로를 정확히 지목한다.
- 그 행동을 마쳤을 때 무엇이 참이 되는지 알 수 있어야 한다.

"계속 진행한다", "검토한다", "확인한다"만 적힌 첫 다음 행동은 재개를 지원하지 않는다.

## 6. 예외

- `quick` 작업은 현재 상태 문서를 갱신하지 않는다.
- 사용자가 전체 단계를 위임한 경우에도 단계 전환마다 상태를 갱신한다. 위임은 기록 의무를 면제하지 않는다.

## 7. 검증

- 작업 도중 세션을 종료하고 다른 에이전트가 상태 문서만으로 재개하게 한다.
- 새 에이전트가 목표, 범위, 금지 사항, 차단, 첫 행동을 재진술하게 한다.
- 완료된 작업의 상세가 시작 문맥에서 제거되었는지 확인한다.
- 현재 상태 정본이 하나뿐인지 확인한다.
