# 현재 상태와 세션 인수인계

- 목적: 소비 저장소의 다른 에이전트나 새 세션이 대화 없이 정확한 중단 지점부터 재개하게 한다.
- 읽는 시점: 작업을 중단·인계하거나 소비 저장소의 현재 상태를 갱신할 때.
- 책임: 작업 에이전트가 선언된 상태를 갱신하고 사용자가 승인 상태를 소유한다.
- 상태: 활성 규칙. L2 작업 계약 계층.
- 관련 권위: [Core 상시 정책](../PROJECT_RULES.md), 소비 저장소의 `agent-core-consumer:v1` 선언.

---

## 1. 상태 정본 찾기

현재 상태의 경로는 Core에 고정하지 않는다. 소비 저장소 정책의 소비 계약 선언에서 `state` 값을 읽고 소비 root 안쪽의 상대경로로 해석한다.

Core 저장소 자체는 현재 상태를 소유하지 않는다. Core 변경 작업의 상태는 `maintainer` 소비 저장소가 소유한다.

## 2. 상태 문서 계약

상태 문서는 다음 절을 갖는다.

| 절 | 내용 |
|---|---|
| 현재 단계 | 활성 단계와 활성 설계 |
| 직전 게이트 | 바로 앞 판정 하나 |
| 승인 상태 | 위임된 것과 위임되지 않은 것 |
| 차단 | 원인과 필요한 결정 |
| 알려진 위험 | 미검증 항목과 해소 시점 |
| 첫 다음 행동 | 번호가 매겨진 구체적 행동 |

## 3. 포함하지 않는 것

- 완료된 단계의 상세 과정과 과거 판정 전체
- 동적 Git 수치와 파일 개수
- 정책·규칙 본문
- 대화 원문과 사용자의 발언 요약
- Core revision SHA 복제
- 다음 세션이 이어서 증가시킬 실패 카운터

완료 상세와 복구 지점은 해당 저장소의 Git commit이 소유한다.

## 4. 조건과 행동

- 단계가 전환되면 현재 단계, 직전 게이트, 승인 상태, 첫 다음 행동을 갱신한다.
- 작업을 중단하면 다음 사람이 실행할 첫 행동과 남은 금지·차단만 기록한다.
- 차단이 생기면 실패한 시도보다 원인·필요 결정·재시작 조건을 기록한다.
- 반복 실패 임계에서 중단하면 실패 유형·확인한 원인·시도한 방법·대체 방법·재시작 조건은 기록하되, 실패 횟수를 다음 세션의 활성 카운터로 승계하지 않는다.
- 중단 절차로 상태 문서를 작성하는 행위는 원 작업의 추가 실패 시도가 아니다.
- 추적되지 않는 로컬 상태에 의존하면 `same-workspace`, 추적된 내용만으로 복원되면 `portable`로 표시한다.
- `quick` 작업은 상태를 갱신하지 않는다.

## 5. 첫 다음 행동

- 실행 가능한 동사로 시작한다.
- 대상 파일·명령·판정 조건을 구체적으로 적는다.
- “계속 진행한다”, “검토한다”, “확인한다”만 적지 않는다.

## 6. 검증

- 선언된 상태 경로가 소비 root 밖으로 나가지 않는지 검사한다.
- 필수 여섯 절, 크기 예산, 동적 수치, 첫 행동 구체성을 검사한다.
- 새 에이전트가 Core 정책·소비 정책·상태만으로 목표·차단·다음 행동을 재진술하게 한다.
- 합성 구조 통과와 실제 cross-agent 재개를 구분해 보고한다.
- 반복 실패 중단 상태를 읽은 새 세션이 이전 카운터를 이어서 증가시키지 않는지 확인한다.
