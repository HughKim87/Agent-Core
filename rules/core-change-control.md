# Core 변경 통제

- 목적: Core를 기본 불변 영역으로 유지하면서 승인된 최소 변경만 검증해 수용한다.
- 읽는 시점: Core로 선언된 경로를 생성·수정·삭제·이동·개명·재생성하거나 간접적으로 바꾸기 전.
- 책임: 사용자가 각 변경 범위를 승인하고 에이전트가 최소 변경과 검증을 수행한다.
- 상태: 활성 규칙. L2 작업 계약 계층.
- 관련 권위: [상시 정책](../POLICY.md) §8이 상위다.

---

## 1. 적용 대상

이 규칙은 Core로 선언된 경로에 적용된다. 어떤 경로가 Core인지는 사용하는 저장소가 선언하며, 이 규칙은 그 선언을 조회한다.

독립 Core 저장소에서는 저장소 전체가 Core다. Core가 다른 프로젝트에 포함되는 경우의 경계 선언은 이 규칙의 범위 밖이다.

## 2. Core 변경의 정의

다음은 모두 Core 변경이다.

- 파일 생성, 수정, 삭제, 이동, 개명
- 파생 artifact의 재생성
- 의존성·설정·도구 체인 변경으로 인한 간접 변경

읽기와 승인된 인터페이스의 실행은 Core 변경이 아니다.

## 3. 승인 조건

Core 변경은 다음이 **모두** 충족될 때만 시작한다.

1. 정확한 이유가 확인되었다.
2. 정확한 대상 범위가 확인되었다.
3. 현재 대화에서 사용자가 그 범위를 승인했다.

상시 목표, 과거 승인, 활성 계획, 추론된 이득, 다른 범위에 대한 승인은 Core 변경을 승인하지 않는다.

**예외:** 사용자가 다단계 작업 전체를 명시적으로 위임한 경우, 그 위임 범위 안의 단계별 변경은 개별 승인을 다시 요구하지 않는다. 위임은 범위를 넓히지 않으며 §5의 검증 의무를 면제하지 않는다.

## 4. 조건과 행동

- **조건**: Core 변경이 승인되었다.
  - **행동**: 승인된 최소 범위만 바꾼다. 근처의 개선 기회를 함께 처리하지 않는다.
- **조건**: 무인·자동·배경·예약 작업이 Core 변경을 필요로 한다.
  - **행동**: Core를 건드리지 않는다. 비성공 결과를 반환하고 차단 사실을 기록한 뒤 그 목표를 종료한다. 승인을 추론하거나 대기하지 않는다.
- **조건**: 변경이 승인 범위를 벗어난다.
  - **행동**: 멈춘다. 벗어난 범위를 보고하고 새 승인을 받는다.
- **조건**: Core 변경이 거부되었다.
  - **행동**: 예상된 안전 정지로 처리한다. 이를 재사용 가능한 실패 지식으로 저장하지 않는다.

## 5. 변경 후 검증

승인된 변경 후에는 통합 검증 게이트를 실행한다.

- 게이트 명령은 특정 디렉터리 이름을 문자로 포함하지 않는다. 검사 대상은 선언에서 조회해 조립한다.
- 게이트가 실행될 수 없는 환경이면 변경을 완료로 처리하지 않는다.
- 실행하지 않은 검사를 통과로 기록하지 않는다.

게이트 명령을 특정 이름에 결합하면 그 이름의 디렉터리가 없는 환경에서 게이트 자체가 실행되지 않고, 그러면 그 환경에서는 Core 변경을 승인할 방법이 사라진다. 이 결합은 명시적 금지 사항이다.

## 6. 범위 대조

변경 완료 전에 실제 변경 목록을 승인된 범위와 대조한다.

- 승인 목록에 없는 경로가 변경되었으면 완료로 처리하지 않는다.
- 도구가 자동 생성한 파일도 대조 대상이다.

## 7. 검증

- 무승인 수정, 승인 범위 밖 수정, 승인된 최소 수정 시나리오를 각각 검사한다.
- Git 상태를 이용해 변경 감지와 범위 대조를 수행한다.
- 무인 작업이 Core를 건드리지 않고 비성공 상태를 남기는지 확인한다.
- 게이트 명령에 하드코딩된 디렉터리 이름이 없는지 확인한다.
