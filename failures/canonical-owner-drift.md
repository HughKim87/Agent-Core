# 정본 드리프트와 문서 증식

- 목적: 같은 사실이 여러 문서에 복제되어 서로 달라지는 실패를 막는다.
- 읽는 시점: 유지 문서를 만들거나 바꿀 때, 상태를 기록할 때.
- 책임: 에이전트가 재발 시 조건과 검증을 보강한다.
- 상태: 해결.
- 관련 권위: 라우터가 선택하는 실패 기록 규칙.

---

## 증상

같은 상태가 여러 문서에 복제되어 서로 달라졌다. 파일명 변경 뒤 오래된 경로가 링크에 남았다. 계획 문서가 분석 원문과 구현 상세를 다시 소유하며 계속 커졌다.

## 조건

문서 유형과 정보 소유 역할을 하나의 축으로 섞어 판단한 상태.

## 확인된 원인

Git과 정본이 이미 보존하는 상태·이력을 파생 문서와 보고서로 다시 표현했다.

## 실패한 접근

문서를 추가로 만들어 정리하려 했다. 정본이 늘어나 드리프트가 악화됐다.

## 해결

활성 정보마다 소유자를 하나로 두고 다른 문서는 링크만 유지한다. 완료 상세는 Git에 맡긴다.

## 검증

링크 검사와 현재 상태 정본 유일성 검사를 실행한다.

## 예방

- 무엇을 소유하는지와 문서 형식을 별도 축으로 판단한다.
- 완료 서사를 현재 상태 문서에 누적하지 않는다.
- 정본이 이미 필요한 정보를 소유하면 별도 파생물을 만들지 않는다.
- 문장을 제거해도 다음 행동·재개·검증 판단이 달라지지 않으면 완료 전에 압축한다.
