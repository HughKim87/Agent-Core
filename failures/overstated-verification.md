# 검증 수준의 과장

- 목적: 도달하지 않은 검증 수준을 도달한 것처럼 보고하는 실패를 막는다.
- 읽는 시점: 완료를 판정하고 보고할 때.
- 책임: 에이전트가 재발 시 조건과 검증을 보강한다.
- 상태: 해결.
- 관련 권위: 라우터가 선택하는 실패 기록 규칙.

---

## 증상

임시 합성 환경의 통과를 실증했다고 보고했다. 이식성 검사 통과를 기능 회귀 검증인 것처럼 보고했다. 실제로는 회귀 다수가 실패 상태였다.

## 조건

여러 종류의 검사를 하나의 통과·실패로 합쳐 보고하는 상태.

## 확인된 원인

검증의 성격을 구분하는 어휘가 없었고, 무엇을 실행하지 않았는지를 보고 항목에 두지 않았다.

## 실패한 접근

통과 개수를 함께 적었다. 어떤 종류의 검사인지가 빠져 있어 과장이 그대로 남았다.

## 해결

검증 수준을 명시적 체계로 나누고 완료 보고에 실행하지 않은 검사와 알려진 한계를 필수 항목으로 넣는다.

## 검증

완료 보고와 실제 검증 로그를 대조한다.

## 예방

- 합성 fixture 통과를 실제 사용 검증이라고 하지 않는다.
- 실행하지 않은 검사는 pass 가 아니라 not_run 이다.
- '실증했다' '전부 통과했다' 대신 어떤 수준의 어떤 검사를 실행했는지 적는다.
- 완료 보고의 알려진 한계 항목이 비어 있으면 대개 확인하지 않은 것이다.
