# 런타임과 텍스트 경계

- 목적: 플랫폼·인코딩·경로 차이에서 오는 실패를 환경 문제로 정확히 진단한다.
- 읽는 시점: 새 환경에서 명령을 실행할 때, 텍스트 파일을 읽고 쓸 때, 설정 경로를 찾을 때.
- 책임: 에이전트가 재발 시 조건과 검증을 보강한다.
- 상태: 해결.
- 관련 권위: 라우터가 선택하는 실패 기록 규칙.

---

## 증상

같은 명령이 환경에 따라 다르게 동작했다. 문서 저장 성공 응답 뒤 디스크 파일이 잘려 있었다. 공식 문서의 설정 경로가 실제 설치본에 없었다.

## 조건

설치 형식, 셸, 기본 인코딩이 문서의 가정과 다른 상태.

## 확인된 원인

환경의 고정 제약과 코드 결함을 분리하지 않고 코드 수정으로 해결하려 했다.

## 실패한 접근

같은 설정을 반복 적용하고 같은 명령을 재시도했다. 원인이 환경이었기 때문에 해결되지 않았다.

## 해결

실행 전에 설치 형식과 실제 프로세스가 읽는 경로를 확인한다. 텍스트는 인코딩을 명시해 읽고 쓴다.

## 검증

쓰기 직후 실제 파일의 크기, 끝부분, 파서 통과를 다시 확인한다.

## 예방

- 도구의 성공 응답만으로 완료 처리하지 않는다.
- 같은 오류가 환경 경계에서 재현되면 코드 수정 전에 환경 제약을 확인한다.
- 권한 밖의 환경 제약이면 즉시 다른 실행 경로를 선택한다.
- 경로가 없거나 수정이 반영되지 않으면 같은 설정을 반복하지 않는다.
