# 원자 쓰기와 상태 무결성

- 목적: 쓰기와 검증 사이의 경쟁 구간과 상태 불일치를 막는다.
- 읽는 시점: 파일 기록, 이벤트 스트림, 스냅샷, 동시 쓰기를 다룰 때.
- 책임: 에이전트가 재발 시 조건과 검증을 보강한다.
- 상태: 해결.
- 관련 권위: 라우터가 선택하는 실패 기록 규칙.

---

## 증상

쓰기 뒤 검증 사이에 경쟁 구간이 생겼다. 이벤트 시각이 역행했다. 저장 주소·ID·유형·완료 상태가 서로 충돌했다.

## 조건

입력 경계만 검증하고 저장된 데이터를 신뢰한 상태.

## 확인된 원인

원장 append와 파생 표현의 성공 조건을 하나의 불변식으로 설계하지 않았다.

## 실패한 접근

사후 검증을 추가했다. 잠금 밖에서 재읽기했기 때문에 경쟁 구간이 남았다.

## 해결

원자 교체와 성공 판정 재읽기를 같은 잠금 경계에 두고 ID에서 저장 주소를 결정한다.

## 검증

저장 유형, 이벤트 시간, 상태 전이, 기대 해시의 정상·실패 회귀를 실행한다.

## 예방

- 성공 판정에 쓰는 해시·개수·버전은 잠금 내부 스냅샷에서 계산한다.
- 중앙 인덱스가 없으면 ID와 저장 주소를 결정론적으로 대응시킨다.
- 입력 허용 목록과 저장된 데이터 유형을 모두 fail-closed 검증한다.
- 종료 상태에는 다음 행동을 남기지 않는다.
